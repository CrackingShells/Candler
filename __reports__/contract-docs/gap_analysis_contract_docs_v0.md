# Gap Analysis: candler-v1 - No contract pages for the agents that use Candler

## Problem Statement
Candler's consumers are coding agents, first LLM-based and then human, that write plug-ins, experiment files or harness drivers. Nothing tells them what Candler expects at each surface, which fields they must set, which they are free to set, or which versions work together. That knowledge is spread across R01, which is written for maintainers, 18 JSON schemas and the Rust types. No roadmap leaf plans contract pages. The contract only freezes at 1.0 (M6), so pages written now would drift unless most of their content is generated and the rest is marked tentative.

## Root Cause
The milestones so far proved parity, both evaluation and execution, against the HTN reference, where Candler's authors were also the plug-in's authors. Nobody outside needed the contract written down, and nothing in the roadmap asked for it. The generated schemas are a good source of truth, but nothing turns them into pages, and refusals have no stable identity that a page could list.

## Impact Assessment
- **Scope:**
  - In: pages for agents, generated where possible, with a fixed frame; and stable codes for the refusals an author can cause, since a page cannot list refusals that have no identity.
  - Out: pages written for humans, tutorials and an authoring skill. Those come after 1.0. The authoring skill is its own deliverable: a skill that guides an agent through writing a plug-in, not a page.
- **Dependencies:** M6's second plug-in is the first one written by someone who only has the contract. The freeze needs the pages to say what freezes.
- **Risk:** pages written by coding agents tend to be long, unstable from one edit to the next, unstructured and wider than asked. A fixed frame, generated tables, a word cap and a stamp on every hand-written note are the counter-measures.

## Proposed Solution: the frame
Pages live under `docs/contract/`, one per surface, plus an index. Their reader is a coding agent: they hold tables and rules, with no narrative, no tutorial, no analogy and no development process.

**Surfaces:**
- for plug-in and experiment authors (M3): the plug-in manifest, the suite file, the evaluator protocol, the outcome record, the experiment file and the `candler-evaluator` helper;
- for harness-driver authors (M4): the driver traits.

**Field classes.** Every field of a surface has exactly one class:

| Class | Meaning |
|:------|:--------|
| `candler` | Candler writes it; an author never sets it |
| `required` | The author must set it; preflight refuses its absence |
| `optional` | The author may set it; Candler applies a stated default |
| `free` | The author's own; Candler stores it and never reads it |

**Page sections**, in this order, and no others:

| Section | Source |
|:--------|:-------|
| Surface: one sentence saying what it is, who writes it and who reads it | Hand-written |
| Version: the line, the current version, and the core and helper versions it works with | Generated |
| Fields: path, type, class, default | Generated from the types or schemas |
| Refusals: code, when, path at fault, side to fix | Generated from the code |
| Notes (tentative): rules the tables cannot state, each stamped with the version it was checked against | Hand-written, at most 120 words per page |

The index holds the compatibility table (`schemas@`, core `v`, `candler-evaluator@`), which is generated.

**Checks**, run by CI:
- regenerating the pages changes nothing;
- the Notes of each page stay within the cap;
- every refusal code in a page exists in the code, and every author-facing code has a page.

## Recommendations
1. **M3** builds the frame, the generator, the CI checks and the refusal codes. It writes the pages for the six surfaces that plug-in and experiment authors meet, and records the frame in `CONTRIBUTING.md`.
2. **M4** writes the driver-traits page in that frame, generated from the trait definitions, and keeps the pages of the surfaces it changes current.
3. **M6** removes the tentative stamp from the pages of every surface that freezes, once each note is checked against 1.0.0.
4. **After 1.0:** pages for humans, and a plug-in authoring skill tested by a fresh agent that has only the pages.
