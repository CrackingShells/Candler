## 2. CLI help text (what `candler --help` would print, from clap definitions)

Top level: `about = "Run, evaluate and compare agent experiments"`; no `long_about`, no `after_help`, no examples. Global flags: `--store` (env `CANDLER_STORE`), `--error-format {text,json}`.

Verbs (doc comments become one-line help):
- `run`: "Starts a job for an experiment." Args: `<experiment>`, `--set PATH=VALUE` (repeatable, JSON-or-text), `--force`.
- `ps` "Lists the jobs and their state."; `kill` "Stops a job." (`--all`, `-y`); `watch` "Follows the events of a job." (`--json` default, `--live`).
- `ingest` (alias `import`) "Ingest raw trace directories, or legacy results folders, into the store." `--rules` makes each path a legacy folder. The flag help for `--rules` says "cannot be derived: how a legacy folder maps to runs is the importer's input", which says nothing about the rules-file format.
- `evaluate` "Grade stored runs with a plug-in's suite." Args: `<suite>`, optional `<job>`, `--runs <glob>`.
- `show` "Print stored outcomes, or their rates." `--rates`, `--evaluator`, `--format` (REQUIRED, no default).
- `diff` "Compare the outcomes of two evaluator versions." `--from`, `--to`, `--equivalence`, `--format` (required).
- `resolve` "Resolves an experiment and prints what its settings come to." `--set`, `--json`.
- `ls`, `analyze` "Reports the statistics of stored outcomes." (`--evaluator`, `--experiment`, `--format`, `--table`), `inspect` "Shows one run, or one job, with its outcomes, evidence, provenance and integrity."
- `supervise` hidden.

Observations: flag docs are written as design rationale ("not an experiment setting: it is how the output is read", "cannot be derived: ...") and leak into `--help`; a consumer agent reads justification where it wants the value domain. `--format` values for `show`/`diff` are enum names not described in the doc comment. Exit codes (0 same, 1 changed, 2 error) are only in the `main.rs` module doc, not in `--help`. No help text says what `ps` prints, what `analyze` outputs, or that `resolve` is the free preflight (no tokens spent).

## 3. Gaps (consumer tasks no document explains), ranked by harm to an agent

1. **No end-to-end walkthrough at all.** Nothing shows "write experiment.toml -> `resolve` -> `run` -> `watch` -> `evaluate` -> `show`/`analyze`". No sample experiment file, suite file, plugin manifest or rules file is in `docs/`. README has no quickstart. (Highest harm: an agent must assemble a valid TOML from tables of typed paths.)
2. **Settings vocabulary is not documented.** `[fixed]`/`factors[].path` accept dotted paths (`model.id`, `model.effort`, `runner.mode`, `runner.idle_s`, `isolation.egress`, `isolation.network`, `isolation.build.plugin`, `mcp.servers.<key>.name`, `request.treatment`...), but the experiment page types them as `map`/`any`. Valid paths surface only via `experiment.unknown_path` refusal, `resolve`, or driver `settings_table()` in Rust. `candler.toml` (project config: `plugins.dirs`, `store.root`, `slots.*`, `gateway.*`) has no page.
3. **Writing an evaluator in Python:** the kind signature, `RunContext` fields, `Prior`, `Outcome`, `KINDS`, how to declare `needs` and `params_schema`, how the helper derives `name/version` from the distribution, instrument pinning (installs must be git/editable; a PyPI install fails with -32000) are in code and two bare examples only. `evaluator-helper.md` documents outcome fields, not the Python API. The helper README is for maintainers.
4. **Refusal recovery.** Codes exist (~395 in `codes.toml`, ~230 in pages) with "When" and "Side to fix", but no "what to do", no mapping to the `refusal/1` JSON that `--error-format json` prints, and the contract pages never mention that flag. Agents calling the CLI default to text.
5. **Reading `analyze` / `show` output.** statistics.md explains methods but not the JSON/CSV schema (`--format`, `--table` values, row names, the `reason` strings such as `weighted`, `too_few_runs`). No sample output. Which table to ask for with `--table` is not documented.
6. **Choosing a budget.** The Budget table (architecture.md 218-233) says per-run caps are a treatment condition and job caps are `budget_stop` ends; `budget.per_run.wall_s` is mandatory. No guidance on sizing wall/turns/cost, on `max_parallel`, on slot pools (`slots.count`, "provisional" default), on cost per run (a separate report `__reports__/agent-token-costs` exists but is not linked from docs). Harness support matrix says opencode refuses turn and cost caps.
7. **Importing legacy results:** `ingest --rules <toml>` format is documented only by refusal texts (`config.import_rules_invalid`, `config.import_field_unset`) and the design doc; no sample rules file.
8. **Install/setup/prereqs:** nothing says how to build or install `candler` (nothing is published), that Docker is required, which env vars/secrets are needed (`secrets` array, gateway credentials), what `candler.toml` looks like, where the store lives (`CANDLER_STORE`), Linux/macOS only (only in a `compile_error!`).
9. **Concepts/glossary:** cell, arm, run key, stratum, block, role (gate/quality/descriptive), treatment, harness, census, gateway, instrument, seal (`run.done`), not defined in one place (the vocabulary is spread across design and refusal texts). Run-key and job-id formats are not documented (design "ids" search found nothing consumer-facing).
10. **Inspecting/interpreting runs:** what `inspect` prints, what the run store layout is (`run-tree.schema.json` exists but undescribed), how to read traces (`normalised-trace`), what `events.jsonl` events mean (event-envelope schema only).
11. **Staleness/dead material in the pages:** retired/lifted/"not raised today" rows; notes stamped `v@0.7.0`/`schemas@0.6.0` against v0.13.0; README does not mention docs/; statistics.md "paired tests not offered" vs closed M6a paired stats (verify).
12. **MCP (M7 itself):** architecture says "MCP server: later", with I13 (budget mandatory on MCP surface), I8 (no ground truth exposure), "read/mutate split" and "mandatory budgets" as planned mitigations; there is no MCP tool list or surface spec to consume yet.
