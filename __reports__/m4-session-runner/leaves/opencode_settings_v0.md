## Answers to the coordinator's three questions

1. **Does a deny rule bind under `--auto`?** Yes, unconditionally. `Permission.denied()` is checked first, using only the agent's and the session's own rules (never the "always"/saved rules), *before* any `ask` event is even published (`packages/core/src/permission.ts:176-178, 262-269`). `--auto` (`packages/cli/src/run/noninteractive.ts:97-112`) only auto-replies a *pending* `ask` request with `"once"` — it has no path that touches a `deny` match at all. This is what lets the `plan` mapping add a `shell` deny rule and trust it to hold even though the run also passes `--auto`.

2. **Does `plan` match Claude Code's plan mode?** Yes, once the driver adds a `shell` deny rule. `plan`'s own built-in rule (`packages/core/src/plugin/plan.ts`, v2.2.7) denies `edit` (covering edit/write/patch) everywhere except its own `.opencode/plan/*` scratch directory, but adds nothing for `shell` — left to `ask`, which `--auto` would approve. The added rule closes exactly that gap (verified by the `oc_plan_mode_blocks_shell` fixture: the model's `shell` tool call is refused). The refusal's wording differs from Claude Code's own plan-mode message (OpenCode's tool is removed from the list entirely — `"No tool named \"shell\" is currently available"` — rather than a `Permission.BlockedError`), but the *outcome* (no shell side effects) is the one Candler's meaning cares about.

3. **Does `steps` count what `--max-turns` counts?** Yes — exactly model requests/turns of the agent loop, not some other unit (HTTP calls, tool calls, etc.). Settled two ways: the upstream test suite (`session-runner.test.ts:5801-5833`, v2.2.7) asserts the same mechanism (the final step's request carries `tool_choice: {type: "none"}`); and the `oc_step_cap` fixture shows `agents.build.steps = 2` producing exactly two tool-bearing requests (matching the exported session's own two assistant turns), the second disabling tools, with no third tool-bearing request following. A third, tool-less HTTP request also reached the fake model in that recording (likely a title/classification call OpenCode makes outside the main agent loop) — it is not itself a step either OpenCode's own trace or the cap counts, and is called out explicitly in the fixture's `exit.toml`/`expected.toml` so the discrepancy between "raw HTTP count" (3) and "steps counted" (2) is not silently hidden.
