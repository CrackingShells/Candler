## 3. How the capability page reads the drivers

The generator compiles `crates/candler/src/drivers.rs` (`#[path]`) with a two-type stand-in for the command layer it names, so the page lists exactly the drivers `Registry::builtin()` registers. Each row has one mapping function.

| row | reads | words |
|:--|:--|:--|
| gateway route | `gateway()` | `Candler: gateway, address in <variable>` |
| census source | `capabilities().census`, `census_stream()` | `yes` (init event) or `Candler: gateway, first request with tools` (`census_init` takes the first request that carries tools) |
| session mode | `capabilities().session` | `yes`, or `no (refused)` (`session_capable@1`) |
| turn cap, cost cap | `capabilities().budgets`; else a refused row of `settings_table()` for the path | `yes` or `no (refused)`; a driver that lacks the cap and declares no refused row stops the generator |
| stop | `stop()`, `capabilities().graceful_stop` | `yes`, or `Candler: interrupt command in the container, then SIGTERM` |
| authoritative trace | `Registry::offline()`, `live_reader()` | `yes`, or `Candler: collects <stream> after the run` |
| skills layout | `SkillTree::archive_command` and `files` on a one-file archive | `yes` when the tree lands where the archive reads it, else `Candler: places the tree at <path>` |

## 6. Findings

1. **Spec defect, gates of the leaf.** The frame and M3's `check_frame` name the last section `Notes` and stamp a note `[checked: <line>@<version>]`. The leaf's gates grep `## Notes (tentative)` and `checked against v[0-9]`. The two existing pages, the generator and D2 use the frame's spelling, so the pages follow it. The gates need rewording; I did not change the frame.
2. **Brief defect.** The L4 brief says the conformance suite no longer checks `census_stream()`. `candler-harness/src/conformance.rs` still reads it (line 712, the census capability needs a stream or an init report; line 871, a stream-sourced inventory must be labelled gateway or collected). The page's Note says only what the doc comment and `runner/exec/mod.rs:678` show: it names the raw stream the gateway's census is stored under, and the core reads that census itself.
3. **Leaf wording.** "Resolve refuses" a setting is not exact: `experiment.setting_unsupported` comes from `driver.command()` (`runner/exec/mod.rs:480`) when a cell runs, and only `experiment.session_refused` comes from a resolve step. The page's Note says so.
4. **Leaf wording, cell form.** A cell is `yes`, `Candler: <how>` or `no (refused)`. The turn cap of a session-capable harness is both: the harness gets `--max-turns` and the session runner ends the run when the turns summed over the session exceed the cap (`SessionWatch::verdict`). The cell says `yes`; a Note carries the second fact.
5. **No declared item for MCP code mode (ruled: row dropped).** No trait item or settings row states it, so the row reads `prepare()` on a probe cell. It tells the drivers apart by whether the written files hold a `codemode` key; it does not say whether Claude Code honours one it is given. If the row should be a declared item, the OpenCode driver needs a `settings_table()` row for it (a change outside OWNED).
6. **Size.** The generator is about 540 lines (`capabilities.rs` 323, `harness.rs` 220), mostly the mappings and the probes: the tar builder of the skills probe is 20 lines. A trait-item parser stands in for `syn`, which is no dependency of the workspace; it reads the four-space `fn` layout rustfmt gives, and a trait that breaks it fails the generator with its name.
7. **Not done.** `rust-conventions:rust-conventions-reviewer` was not run (the L4 process leaves review to the one verifier); the coordinator regenerates the pages at merge if `codes.toml` gains a code from `session_controls`.

## 7. Fix round

Ruled by the coordinator: the MCP code mode row and its probe are removed (8 rows remain, to return once `mcp.codemode` is declared in each `settings_table()`); the trait parser is `syn` 2 (dev-dependencies `syn` with `full` and `proc-macro2` with `span-locations`; `Cargo.lock` gains the two names in `candler`'s dependency list and nothing else). Both bites re-applied and restored from copies: OpenCode declaring `session` fails at line 22 of `harness-capabilities.md`; a new `SkillTree` item fails at line 59 of `driver-traits.md`.
