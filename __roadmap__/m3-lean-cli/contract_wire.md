## Step 1: Probe P3 and write the oracles by hand
**Goal**: P3's answers decide how `optional` is read from the schemas, and the hand-written oracles of C1, C3 and C4 are committed before any type exists.
**Implementation Logic**:
1. **Probe P3** in a throwaway test or example under the target dir; nothing of it is committed. Answer in the leaf report:
   - After `OmitNull`, does schemars emit `default` for a field with `#[serde(default)]`, for `default = "one"`, and for the crate's `present`-deserialised `Option`? Is every non-`required` property either one of these or an `Option`? The reading rule for `optional` (D4: not in `required`) holds only if so.
   - Does `#[schemars(extend("x-candler-class" = "candler"))]` on a field land on its property, both for a plain type and for a `$ref` field (a sibling of `$ref` under 2020-12)? On a `#[serde(remote = "Self")]` type (the crate uses it widely)?
   - Does `datamodel-codegen` (the version `uv.lock` pins) copy an `x-` keyword into the helper's models, and do the models still pass `ruff format --check` and pytest? The models are regenerated in Step 4 whatever the answer is; a keyword that breaks them stops the leaf: report it.
   - Does `serde_path_to_error` over `toml::Deserializer` and over `serde_json::Value` name an unknown field itself or its parent, for a type with `deny_unknown_fields`, for a `MapOnly` wrapper and for a `remote = "Self"` type? C3's oracle names the field itself; if the library gives the parent, Step 3 appends the key from serde's `unknown_field` error.
2. Enumerate the enums from `__roadmap__/m3-lean-cli/refusal_scope.tsv`: the rows whose file is under `crates/candler-schemas/src` and whose author-facing column says yes. Today's candidates, to check against it: `ExecutionError` (24), `EvaluationError` (9), `OutcomeError` (16), `FormatError` (20), `CanonicalError` (5), `ValuesError` (2), and the structs `SchemaTagError` and `VersionMismatch`. Out, with a reason each in the tsv: `TraceError`, `RawError` (M4's), `CatalogError`, `ContainerError`, `ProcessError` (Candler writes those records) and `SchemaFileError` (tooling). A disagreement between the tsv and this list goes to the coordinator before Step 2.
3. Write `crates/candler-schemas/tests/vectors/refusals/records.json`: hand-written `refusal/1` records, valid and invalid (a record with an unknown field, with `code` as a number, with a side outside the six, with `causes` missing, with neither `path` nor `file`, with both). C1 reads it.
4. Write `crates/candler-schemas/tests/vectors/refusals/pointers.toml`: for each of the experiment file, the suite and the plug-in manifest, malformed texts with the RFC 6901 pointer a person would give: an unknown nested field (`/budget/max_paralel`), a wrong type (`/replicates`), a missing required field (the parent pointer and the field's name), an unknown top-level key, a wrong `schema` tag (`/schema`), an item of an array (`/expectations/1/id`), a key holding `/` or `~` (`~1`, `~0`). For the experiment file the pointer is into the document as Candler reads it, after the TOML-to-JSON step: `fixed` is flat, so a key `plan.model` is `/fixed/plan.model`.
5. Write `crates/candler-schemas/tests/vectors/field_classes.toml`: every property of the nine schema files of the six surfaces, by file and dotted path, with its class. Roots: `plugin-manifest`, `suite`, `experiment`, `outcome-record`, and the five `evaluator-*` files (`describe-result`, `evaluate-params`, `message`, `notification`, `request-side`). The helper has no schema file of its own; it is covered through its models' roots, and its page's Fields come from the same nine. Classify by the frame: `candler` is what Candler writes and an author never sets; `free` is stored and never read; the rest by `required`/`optional`. A map-valued property (`fixed`, a suite entry's `params`, a `Value`) is one field. Hand-classify; do not run the generator to fill it. Required sample rows (R10 C4): `budget.max_parallel` optional; `treatment.name` required; one `candler` row; one `free` row; and `schema` of the three author-written documents is `required` (see Spec defects in the report: R10's sample lists it as `candler`, but the author writes it and it is in `required`).
**Deliverables**: `crates/candler-schemas/tests/vectors/refusals/records.json`; `crates/candler-schemas/tests/vectors/refusals/pointers.toml`; `crates/candler-schemas/tests/vectors/field_classes.toml`
**Consistency Checks**: `test -f crates/candler-schemas/tests/vectors/field_classes.toml && jq -e . crates/candler-schemas/tests/vectors/refusals/records.json >/dev/null && git diff --quiet HEAD -- crates/candler-schemas/src crates/candler-schemas/schema && cargo nextest run -p candler-schemas --no-tests=fail` (expected: PASS)
**Commit**: `test(schemas): pin the refusal, pointer and class oracles by hand`

## Step 2: Register the schemas' codes
**Goal**: `codes.toml [schemas]` holds a row for every variant of the author-facing enums, written from the variant list before the impls exist.
**Implementation Logic**:
1. In `docs/contract/codes.toml`, append inside `[schemas]` only. One row per variant: code `<surface>.<reason>`, side, surface, the enum and variant it names. Reasons name the cause, never the implementation (`experiment.path_overlap`, `outcome.cause_missing`, `suite.dependency_unknown`).
2. Surfaces: `experiment`, `suite`, `manifest`, `outcome`, `protocol`, plus `format`, `canonical`, `values` for the shared enums.
3. **Wrapping variants** (`#[error(transparent)]` over a `#[from]`: `ExecutionError::{Format, Values, Canonical}`, `OutcomeError::Format`, `EvaluationError::Canonical`) own no row: they return the inner variant's code and path, and the registry marks them `delegates`. Their side is the wrapper's, because the side belongs to the document being read, not to the string rule that failed. A shared enum's own rows carry the side of its most frequent author per the tsv.
4. Never `candler` for an author error (A5). A code is never renamed after this commit: read the list twice. It is the oracle of C2 and of the helper and page leaves.
**Deliverables**: `docs/contract/codes.toml`: `[schemas]` rows, one per variant of the enums Step 1 listed
**Consistency Checks**: `git diff --quiet HEAD -- crates && git diff --numstat HEAD -- docs/contract/codes.toml | awk '$2!=0{b=1}END{exit b}'` (expected: PASS)
**Commit**: `docs(schemas): register the codes of the schemas' refusals`

## Step 3: The refusal wire, guards first
**Goal**: `Refusal`, `refusal/1`, the impls, the pointers, the class declarations and the doc fix exist, with their guards seen red first, and the schema files are blessed in one commit.
**Implementation Logic**:
1. Create `src/refusal.rs` with only the trait, `Side`, `RefusalCode` and `RefusalRecord`, with stub bodies, and write C1–C4 against them. Run them and see each go red for its own reason (a stub `code()` fails C2; no path fails C3; no declaration fails C4). Record the failures for the report. Do not commit this state.
2. `src/refusal.rs` (`pub mod refusal;` in `lib.rs`; its roots join `generate.rs`'s module list):
   - `pub trait Refusal { fn code(&self) -> RefusalCode; fn side(&self) -> Side; fn path(&self) -> Option<String>; }`, where `path` is an RFC 6901 pointer, and a variant that names a file or nothing returns `None`.
   - `Side { Plugin, Suite, Experiment, Config, Environment, Candler }` (`#[non_exhaustive]`), serialised lowercase. It is a different type from `evaluation::Side` (core or plug-in to upgrade): name the two in each other's docs.
   - `RefusalCode`, a newtype over the text, checked against `^[a-z]+(\.[a-z_]+)+$`, serialised as that text.
   - `RefusalRecord { schema, code, side, path?, file?, message, causes }`, `deny_unknown_fields`, tag `refusal/1` through the crate's `text_type!`/`ManifestSchemaTag`-style marker like the other roots, `causes: Vec<String>` always written, `path` and `file` omitted when absent and not both set. `roots()` yields `refusal-record`.
   - Each public type has doc comments in the crate's style; `missing_docs` is a warning gate.
3. `src/refusal_impls.rs` (private module): `impl Refusal` for the enums Step 1 listed. One exported declarative macro, `refusal_table!` in `refusal.rs` (`#[macro_export]`, so `candler-core`, the harness crates and the binary use it for their own enums), takes `Enum { Variant{..} => ("code", Side, "when", "at"), Delegating(..) => delegate, … }` (`when`: one sentence saying when the refusal arises; `at`: what `path()` points at, or `-`; both written for a coding agent, because the contract pages' Refusals tables are generated from them) and generates both the `code()`/`side()` match, exhaustive with no wildcard (the workspace denies `wildcard_enum_match_arm`), and the enum's `ROWS: &[CatalogRow]`. A variant added without a row then fails to compile, and the rows cannot drift from the match. `CatalogRow { enum_name, variant, code, side, when, at, delegates }` and `pub fn catalog() -> Vec<CatalogRow>` (this crate's rows) are public: `candler_core::refusal::catalog()` (L1) concatenates every crate's. `path()` is written by hand, beside the macro call, and returns the pointer where the variant carries one (`PathOverlap { first, .. }` gives the first path as a pointer, `InputDeclaration` gives `/inputs`…); read each variant's fields and decide, never invent one. `SchemaTagError` gives `/schema`. `VersionMismatch` is `protocol.version_mismatch`. `TraceError` and `RawError` get no impl and `trace.rs` stays untouched.
4. **Pointers through the parsers.** Add a `path: String` field (the pointer, empty at the root) to `EvaluationError::{Toml, Json}` and `ExecutionError::{Toml, Document}`; the `#[error(...)]` text stays byte for byte as it is, so no CLI text moves. Parse through `serde_path_to_error`, converting its path to a pointer (escaping `~` and `/`):
   - `PluginManifest::from_toml_str` (`evaluation.rs`);
   - `SuiteFile::from_toml_str` and `from_json_str` (`evaluation.rs`);
   - `ExperimentFile::from_toml_str` (`execution.rs`), whose second stage is `serde_json::from_value` over the converted document.
   Honour P3 for unknown fields. Nothing else in the workspace constructs these variants; if something does, stop and report it.
5. **Classes.** `#[schemars(extend("x-candler-class" = "candler"))]` or `"free"` on the properties of the nine files that Step 1's table classes so; `required` and `optional` are never declared. Keep to what P3 showed works. The keyword adds no constraint, so no accepted document changes.
6. `TreatmentSpec.source` doc (`execution.rs`): say the path is relative to the experiment file, or to the working directory when `--set` gives it, and that it is recorded absolute and normalised. The schema's `description` changes with it.
7. `schema/README.md` (the crate's own): add `refusal-record.schema.json` to the roots table. Run DRIFT with `CANDLER_BLESS_SCHEMAS=1`. Check with `git diff --stat -- crates/candler-schemas/schema` that the changed files are the new root, the nine files, and `experiment` for the doc.
8. Commit once. The body states that `experiment/1`, `suite/1`, `plugin-manifest/1` and the outcome record keep their tags (the keyword and the doc add no constraint), that `refusal/1` is new, that no message text changed, and that `TraceError` and `RawError` are left for M4.
**Deliverables**: `crates/candler-schemas/src/refusal.rs`: `Refusal`, `Side`, `RefusalCode`, `RefusalRecord`, `CatalogRow`, `catalog`, `refusal_table!`, `roots`; `crates/candler-schemas/src/refusal_impls.rs`: the impls; `crates/candler-schemas/src/lib.rs`: `pub mod refusal; mod refusal_impls;`; `crates/candler-schemas/src/generate.rs`: `refusal::roots()` in `generated_schemas`; `crates/candler-schemas/src/evaluation.rs`: `PluginManifest::from_toml_str`, `SuiteFile::from_toml_str`, `SuiteFile::from_json_str`, `EvaluationError::{Toml, Json}` with `path`, class declarations; `crates/candler-schemas/src/execution.rs`: `ExperimentFile::from_toml_str`, `ExecutionError::{Toml, Document}` with `path`, `TreatmentSpec::source` doc, class declarations; `crates/candler-schemas/src/outcome.rs`: class declarations; `crates/candler-schemas/schema/*.schema.json` (blessed, plus `refusal-record.schema.json`); `crates/candler-schemas/schema/README.md`; `crates/candler-schemas/tests/guard_refusal.rs`: `c1_…`, `c2_…`, `c3_…`, `c4_…` (each doc with `Guards:`, `Oracle:`, `Bite:`)
**Consistency Checks**: `cargo nextest run -p candler-schemas --no-tests=fail && cargo check --workspace --all-targets && CANDLER_BLESS_SCHEMAS=1 cargo nextest run -p candler-schemas -E 'binary(schema_drift)' && test -z "$(git status --porcelain crates/candler-schemas/schema)"` (expected: PASS)
**Commit**: `feat(schemas): add the refusal record and field classes`

## Step 4: Regenerate the helper's models
**Goal**: The helper's models carry the sha256 of the schemas as they now are.
**Implementation Logic**:
1. From `python/candler-evaluator`: `uv run --frozen python scripts/gen_models.py`. The script reads the five `evaluator-*` files and `outcome-record`, whose headers pin each file's sha256; the commit is needed whenever Step 3 changed one of them, which declaring classes on them does.
2. Run the helper's pytest, `ruff check` and `ruff format --check`. A models diff beyond the headers is reported with P3's answer, never hand-edited.
3. Touch nothing outside `_models/`. The helper's version bump is the release job's.
