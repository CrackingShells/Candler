## Step 1: Record the second engine's values
**Goal**: Vector files written by scipy and statsmodels, which import nothing from Candler, exist before any Rust method does, so the history shows the oracle came first.
**Implementation Logic**:
1. `gen_stats.py` runs under `uv run --no-project --with scipy==<v> --with statsmodels==<v>`. It reads no Candler file. It writes the six files below with every float as Python's `repr` (17 significant digits). `--check` regenerates in memory and compares each value with relative tolerance 1e-12, so a patch release of an engine does not break it; it exits 1 and names the first differing row. Each file begins with an `[engine]` table: `scipy`, `statsmodels`, `python`, and where it applies the tie tolerance. Run it once with no flag to write the files.
2. `wilson.toml`: rows `{k, n, lo, hi}` for n in {1, 2, 3, 5, 10, 20, 30, 100} and every k from 0 to n. Source: statsmodels `proportion_confint(k, n, alpha=0.05, method="wilson")`. The generator asserts that scipy's `binomtest(k, n).proportion_ci(method="wilson")` gives the same values to 1e-12, so the vector is not one library's quirk.
3. `fisher.toml`: rows `{k1, n1, k2, n2, p, tie}` for n1 and n2 each in {1, 3, 5, 10}, every k1 and k2, plus 40 rows with n in {20, 30} that the generator picks with a fixed `random.Random(20261111)`. Source: `scipy.stats.fisher_exact([[k1, n1-k1], [k2, n2-k2]], alternative="two-sided")`, `p` being the second value. `tie = true` marks each row where the strict sum (the tables whose probability is at most the observed one, floats compared with no tolerance, computed in Python from `scipy.stats.hypergeom.pmf`) differs from scipy's by more than 1e-9: those are the rows where scipy's relative tolerance on equal probabilities decides the answer. The generator requires at least 5 such rows and fails otherwise. Read the pinned scipy's `fisher_exact` source for the relative tolerance of its two-sided branch and record the number in `[engine] tie_tolerance`; Step 2 uses the same number.
4. `newcombe.toml`: rows `{k1, n1, k2, n2, diff, lo, hi}` for n1 and n2 each in {1, 5, 10, 30} and every k1 and k2 for n in {1, 5, 10}, and k in {0, 1, n/2 rounded down, n-1, n} for n = 30. Source: statsmodels `confint_proportions_2indep(k1, n1, k2, n2, method="newcomb", compare="diff", alpha=0.05)`, with `diff = k1/n1 - k2/n2`. The generator also re-derives each interval from scipy's Wilson limits with Newcombe's formula (lower = d minus the root of the sum of squares (p1 minus l1) and (u2 minus p2); upper = d plus the root of (u1 minus p1) and (p2 minus l2)) and asserts the two agree to 1e-9.
5. `holm.toml`: rows `{p = [...], adjusted = [...]}`. Source: statsmodels `multipletests(p, alpha=0.05, method="holm")[1]`. Hand rows, written in the generator: m = 1; two equal p-values; three equal p-values; all zeros; all ones; a descending list; an ascending list; a list whose first adjusted value exceeds 1 and is capped; ties that straddle 0.05 after adjustment; m = 20 with one small and nineteen large values. Then 200 lists of length 2 to 20 drawn from `random.Random(20261111)`, written verbatim so Rust needs no generator.
6. `coverage.toml`: rows `{n, p, coverage}` for n in {5, 10, 30} and p in {0.1, 0.5, 0.9}, with `coverage = sum over k of binom.pmf(k, n, p) * [lo_k <= p <= hi_k]`, the limits from statsmodels' Wilson. Exact, no simulation.
7. `power.toml`: one row `{n = 10, p_a = 0.2, p_b = 0.8, alpha = 0.05, power}`, with `power = sum over (k1, k2) of binom.pmf(k1, 10, 0.2) * binom.pmf(k2, 10, 0.8) * [fisher_exact p < 0.05]`.
8. Commit the generator and the six files together, with no `src/` and no `guard_stats.rs`.
**Deliverables**: `crates/candler-core/tests/vectors/stats/gen_stats.py` (`--check`); `crates/candler-core/tests/vectors/stats/{wilson,fisher,newcombe,holm,coverage,power}.toml`
**Consistency Checks**: `uv run --no-project --with scipy==<v> --with statsmodels==<v> python crates/candler-core/tests/vectors/stats/gen_stats.py --check` (expected: PASS); `test "$(git diff --name-only <base>..HEAD | grep -vc '^crates/candler-core/tests/vectors/stats/')" -eq 0` (expected: PASS)
**Commit**: `test(stats): record scipy and statsmodels values for the battery`

## Step 2: The four methods, guards first
**Goal**: Wilson, Fisher (two-sided), Newcombe and Holm exist in `candler_core::analysis` and equal the second engine's values.
**Implementation Logic**:
1. Write `tests/guard_stats.rs` with the T1 guards first, against stub signatures that return `StatsError::NotComputed`, and see every `t1_` guard fail. The test file reads the vector files through `toml` (already a dependency) with `env!("CARGO_MANIFEST_DIR")`. Tolerances: Wilson and Newcombe 1e-9 absolute; Fisher's p 1e-10 absolute, and `p < ALPHA` must agree on every row; Holm 1e-12. Guards: `t1_wilson_matches_the_second_engine`, `t1_fisher_two_sided_matches_the_second_engine`, `t1_fisher_ties_follow_the_tolerance` (the `tie` rows alone, so the bite names them), `t1_newcombe_matches_the_second_engine`, `t1_holm_matches_the_second_engine`, `t1_edges_hold` (k = 0, k = n, n = 1, and the refusals: n = 0, k above n, a p outside [0, 1], NaN). Each doc has `Guards:`, `Oracle:` and `Bite:` lines.
2. `analysis/mod.rs`: `pub const ALPHA: f64 = 0.05;` with its source `ValueSource::CoreDefault` (I12), exposed as `pub const fn alpha_source() -> ValueSource` only if `ValueSource::CoreDefault` can be built in a const context, else as a plain `fn`. `pub fn z_two_sided() -> Result<f64, StatsError>`: `Normal::new(0.0, 1.0)` and `inverse_cdf(1.0 - ALPHA / 2.0)` from statrs. A guard row asserts it is 1.959963984540054 to 1e-12.
3. `analysis/error.rs`: `StatsError` with `thiserror`, `#[non_exhaustive]`: `NoRuns`, `CountAboveRuns { k, n }`, `CountTooLarge { n }` (above 2^53, where a count stops being exact as `f64`), `NotAProbability { index }`, `NotComputed`, and `Distribution(String)` for statrs' own error. It is an author-facing enum only if an author can reach it; none can (the inputs are counts the store holds), so the leaf adds no `Refusal` impl and lists nothing in `codes.toml`: `refusal_scope.tsv` classes it internal. Report that classification to the coordinator.
4. `analysis/wilson.rs`: `Counts::new(k, n) -> Result<Counts, StatsError>` (refuses k above n; n = 0 is a valid count that `wilson` refuses), accessors `k()` and `n()`; `Interval { lo, hi }` with accessors; `wilson(counts) -> Result<Interval, StatsError>` with the score interval at `z_two_sided()`, limits clamped to [0, 1]. One private `to_f64(u64) -> f64` is the only integer-to-float conversion in the module, annotated `// CAST:`, after `CountTooLarge` has been ruled out.
5. `analysis/fisher.rs`: `pub const TIE_TOLERANCE: f64` = the number Step 1 recorded in `[engine] tie_tolerance`; `fisher_two_sided(a: Counts, b: Counts) -> Result<f64, StatsError>`. The table is `[[a.k, a.n - a.k], [b.k, b.n - b.k]]`. With statrs `Hypergeometric::new(a.n + b.n, a.k + b.k, a.n)`, over the support from `max(0, a.n + K - N)` to `min(a.n, K)` (K = a.k + b.k, N = a.n + b.n), the p-value is the sum of `pmf(x)` over every x with `pmf(x) <= pmf(a.k) * (1.0 + TIE_TOLERANCE)`, capped at 1. That is the definition scipy and R use: the tables no more likely than the observed one, never twice the smaller tail.
6. `analysis/newcombe.rs`: `Difference { diff, lo, hi }` (`diff` = a's proportion minus b's) and `newcombe_difference(a: Counts, b: Counts) -> Result<Difference, StatsError>`, the hybrid score interval of Newcombe (1998) method 10, which has no continuity correction, built from two `wilson` calls and clamped to [-1, 1].
7. `analysis/holm.rs`: `holm(p: &[f64]) -> Result<Vec<f64>, StatsError>`. Sort ascending by `(p, index)`; the adjusted value at sorted rank i (from 1, m values) is `min(1, max over j <= i of (m - j + 1) * p_j)`; return the values in the input order. An empty list gives an empty list; a NaN or a value outside [0, 1] is `NotAProbability`. `pub fn rejected(adjusted: &[f64]) -> Vec<bool>` is `adjusted < ALPHA`.
8. `lib.rs`: add `pub mod analysis;` in alphabetical place, as an added line only (the crate doc's module list is left alone, so the OWNED gate's no-deletion check holds).
**Deliverables**: `crates/candler-core/src/analysis/mod.rs`: `ALPHA`, `z_two_sided`; `analysis/error.rs`: `StatsError`; `analysis/wilson.rs`: `Counts`, `Interval`, `wilson`; `analysis/fisher.rs`: `TIE_TOLERANCE`, `fisher_two_sided`; `analysis/newcombe.rs`: `Difference`, `newcombe_difference`; `analysis/holm.rs`: `holm`, `rejected`; `crates/candler-core/src/lib.rs`: `pub mod analysis;`; `crates/candler-core/tests/guard_stats.rs`: the `t1_` guards

## Step 3: The rate algebra
**Goal**: A selection of outcomes plus the validity of its runs becomes, per arm, every count R01's rate rules ask for, and no number without its counts.
**Implementation Logic**:
1. Write the `t3_` guards first and see them fail. Rows are outcome sets built with `OutcomeRecord::builder()` and hand counts, as `tests/guard_selection.rs` does. Guards: `t3_blocked_counts_as_a_failure`, `t3_excluded_statuses_are_counted_with_their_causes`, `t3_invalid_runs_are_out_per_arm_with_their_reason`, `t3_experimenter_ends_are_not_charged_to_an_arm`, `t3_weights_make_an_expectation_non_binary`, `t3_zero_weight_passes_add_nothing`, `t3_roles_sum_as_rates_does` (when every run is valid, each cell's per-role sums equal `evaluation::selection::rates::rates` on the same selection), `t3_every_rate_carries_its_counts`.
2. `analysis/tally.rs`:
   - `RunFacts { run: RunKey, integrity: Integrity }` (the caller reads the manifests), and `tally(selection: &Selection, evaluator: &NameVersion, runs: &[RunFacts]) -> Result<BTreeMap<CellKey, ArmTally>, StatsError>`. A current record whose run is not in `runs` is `StatsError::RunNotListed` (validity is unknown, so nothing is guessed). The arm is the cell of the run key (`CellKey`, reused from `selection::rates`).
   - `ArmTally` holds, per arm: `valid_runs`; `invalid: BTreeMap<String, u64>` (reason name -> runs) for the reasons an arm can own; `experimenter_ends: BTreeMap<String, u64>` for `budget_stop`, `killed` and `interrupted` (I20: never charged to an arm, kept apart so no reader sums them as failures); and `expectations: BTreeMap<ExpectationId, ExpectationTally>`. The reason name is the string of the reason's serde form, so that no match on the `#[non_exhaustive]` `InvalidReason` is needed, and the experimenter set is `matches!(reason, InvalidReason::BudgetStop | InvalidReason::Killed | InvalidReason::Interrupted)`. A run counts in the maps by run key, whatever its records.
   - Records of an invalid run are in neither k nor n (I10): they are dropped before counting, and the run is counted once in its map.
   - `ExpectationTally` holds the role (copied from the outcomes, I21), `pass`, `fail`, `blocked`, `not_measured: BTreeMap<String, u64>` and `not_applicable: BTreeMap<String, u64>` (cause -> records), `zero_weight: u64`, `num`, `den`, and `binary: bool`. The cause key is `"<kind>:<value>"` from the serialised one-key object of `Cause` (`reason:instrument_error`, `artifact:<path>`, `expectation:<id>`, `legacy:<code>`), so no match on `#[non_exhaustive]` `Cause` is needed.
   - Counting, per current record of a valid run: `pass`, `fail` and `blocked` count in n (`blocked` is a failure, R01); `not_measured` and `not_applicable` are out of n and counted with their cause; a `pass` whose effective weight is 0/0 is out of n and out of k, counted in `zero_weight`, and adds nothing to the sums (as `rates` does); `num` and `den` are the sums of the effective weights of the counted records. `binary` is true when every counted record's effective weight is 1/1 or 0/1; otherwise Wilson and the comparisons are omitted for this expectation, with the reason `weighted`.
   - `k()` is `pass` and `n()` is `pass + fail + blocked`, both given only through `fn counts(&self) -> Result<Counts, Omitted>` where `Omitted` is `{ Weighted, NoRuns }` (n = 0). `fn wilson(&self) -> Result<Interval, Omitted>` is built on it.
   - `Rate { num, den }` with accessors and no constructor from a float: a rate is a pair of counts (I2). `ArmTally::rate(role) -> Rate` sums `num` and `den` over the role's expectations. A descriptive role has no rate and is tallied by status only.
   - Descriptive records never enter k, n or a rate.
3. Nothing in this module reads the store or the clock.
**Deliverables**: `crates/candler-core/src/analysis/tally.rs`: `RunFacts`, `tally`, `ArmTally`, `ExpectationTally`, `Omitted`, `Rate`; `crates/candler-core/src/analysis/mod.rs`: `pub mod tally;`; `crates/candler-core/tests/guard_stats.rs`: the `t3_` guards

## Step 4: The battery against known truth
**Goal**: The code `analyze` runs is seen rejecting where a difference is planted and not rejecting where none is, on data whose truth is known.
**Implementation Logic**:
1. The RNG is `rand_chacha::ChaCha8Rng` through `rand_chacha::rand_core::{RngCore, SeedableRng}`, seeded with `seed_from_u64`; no other `rand` crate. A pass probability is a rational `num/den`, drawn as `rng.next_u64() % den < num`, so no float and no cast enter the draw.
2. `t2_wilson_coverage_is_exact`: for n in {5, 10, 30} and p in {0.1, 0.5, 0.9}, the coverage is the sum over k from 0 to n of the binomial probability (statrs `Binomial`) times whether p lies in `wilson(Counts::new(k, n))`. It must equal `coverage.toml`'s value to 1e-9 and be at least 0.91. **Deviation from R10 D8, recorded for Eliott** (accepted by the coordination session on 2026-11-11, pending Eliott's review; nothing waits on it): D8 set the bar at ≥ 0.93, which Wilson cannot meet at small n. The exact coverage at n = 5, p = 0.1 is 0.9185 (k = 0 and k = 1 are covered: 0.59049 + 0.32805), and at n = 10, p = 0.1 it is 0.9298. A fixed bar cannot hold there, so the check is exact equality with scipy's table plus a floor of 0.91, which the Wald interval fails by far. The commit that adds this guard says so in its body, with the 0.9185 figure. Doc: the bite is the continuity-corrected Wilson, which the equality catches, and the Wald interval, which the floor catches.
3. `t2_family_wise_error_holds_under_h0`: two arms of n runs and m expectations with the same pass probability in both, so every null is true. For each scenario and each of 2,000 replications (`REPLICATIONS`), draw every run's outcomes, take `fisher_two_sided` per expectation (through a table of the (n + 1)^2 p-values computed once per n by calling the function), `holm` across the m, and record whether any adjusted p is below `ALPHA`. The share of replications with a false rejection must be at most `0.05 + 2 * sqrt(0.05 * 0.95 / 2000)`. Scenarios: n in {5, 10, 30}, m in {1, 5, 20}, p in {1/5, 1/2} (18), plus one correlated scenario at n = 10, m = 20: each run draws a shared flag, good with probability 1/2, and then every expectation passes with probability 4/5 when good and 1/5 when bad, the same in both arms, so the null is true and the expectations are strongly correlated. Seeds: scenario index, written in the test. The report lists each scenario's observed rate (expected well below 0.05, since Fisher's test is conservative).
4. `t2_power_is_found`: n = 10, p_a = 1/5, p_b = 4/5, m = 1, 2,000 replications. The Rust code's exact power (the sum over (k1, k2) of the two binomial probabilities times `fisher_two_sided(..) < ALPHA`) must equal `power.toml` to 1e-9, and the simulated rejection rate must be at least that power minus `2 * sqrt(power * (1 - power) / 2000)`. This is the positive control: it shows the battery can find a difference, not only that it never cries wolf.
5. Tests are seen red by mutation before the commit (the bites listed under Success Gates), and each mutation is reverted. The cost is about 400,000 Fisher tests; if the `t2_` guards take more than 30 s in a debug build, report it instead of lowering the replications.
**Deliverables**: `crates/candler-core/tests/guard_stats.rs`: `t2_wilson_coverage_is_exact`, `t2_family_wise_error_holds_under_h0`, `t2_power_is_found`, and the constant `REPLICATIONS = 2000`
**Consistency Checks**: `cargo nextest run -p candler-core --no-tests=fail -E 'test(/^t2_/)'` (expected: PASS); `git diff --quiet HEAD -- crates/candler-core/src` once every bite is reverted (expected: PASS)

## Step 5: The page for human readers
**Goal**: `docs/statistics.md` tells a reader what `analyze` computes by default, why, and where it stops being valid.
**Implementation Logic**:
1. Open with the framing: these are Candler's defaults, not the analysis. `analyze` reports every count per run and per expectation (I2), so an author can analyse the same results their own way, through their evaluators or their own post-processing. 2. One section per method, in this order: Wilson interval, Newcombe difference interval, Fisher's exact test, Holm adjustment, and Bonferroni as the rejected baseline.
