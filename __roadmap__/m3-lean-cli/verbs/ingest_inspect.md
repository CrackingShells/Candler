## Step 2: Raw Claude Code trace directories
**Goal**: `import/raw.rs` turns each Claude Code stream of a directory into one sealed run, the same run when ingested again, with relative paths only and its own refusals.
**Implementation Logic**:
1. Write the guards first (`crates/candler/tests/guard_ingest.rs`, fixtures built in a temp dir: streams cut from `crates/candler-core/tests/fixtures/mini-corpus` or written by hand with an init line `{"type":"system","subtype":"init","claude_code_version":"2.1.220", ...}` and a result line) and see them red against the missing verb path. `i1_` guards: `i1_each_stream_becomes_one_run` (a directory with three streams, one unrecognised file and one nested stream gives three runs and one entry in `skipped`, each with `import.sources` holding the stream's path relative to the ingested directory and its sha256), `i1_stored_paths_are_relative` (no manifest field and no source path starts with `/` or holds the temp dir's text), `i1_ingesting_again_creates_nothing` (second call: `created` 0, `existing` 3, the runs directory's file digests equal), `i1_an_unsupported_version_is_an_invalid_run` (an init line with `claude_code_version` 2.0.0 gives a run `invalid {format_unknown}` with the raw kept), `i1_a_directory_with_no_stream_is_refused`.
2. `import/raw.rs`:
   - `pub fn find_streams(path: &Path) -> Result<Vec<Found>, RawIngestError>` walks the path (a directory recursively, in sorted order, never following a symbolic link out of it; a file is a directory of one), reads at most the first 64 KiB of each regular file `*.jsonl` or `*.jsonl.gz` (decompressed in memory for `.gz`) and keeps the files whose first non-blank line `detect::init_version` names a Claude Code version. A recognised stream is `Found { rel: RelPath, bytes_digest: Digest, version: semver::Version, supported: bool }` where `supported` is `detect::supports(&version)`. A file that is not a stream goes to `skipped` with its reason (`not_a_stream`, `unreadable`); the call refuses (`RawIngestError::NoStream`) when it finds none.
   - `pub fn ingest_raw(store: &Store, path: &Path, reader: &ReaderFactory) -> Result<RawReport, RawIngestError>`: streams are taken in the order of their sha256, so any set yields the same keys on a fresh store. Per stream:
     - the cell is the digest of a `comparable` that holds only what the stream states: `harness {name: claude-code, version}`, a treatment named `unrecorded` (the manifest requires one and the stream names none; if P2's recorded answer says otherwise, follow it), no snapshot, no input, no value; and the values recorded `unrecorded` where the typed roots demand an entry, as `import/manifest.rs` does for `sources`;
     - a stream already in the store (a sealed run whose `import.sources` holds this sha256 at this relative path) is `existing` and is not written again, whatever its key; a new stream takes replicate `1 + the highest replicate of its cell in the store` and attempt 1, so a resumed ingest assigns the keys a fresh one would;
     - the run is written like `import/assemble.rs` writes a legacy run: `RunWriter::create(store, &manifest, Existing::ReplaceUnfinished)`, the frames of the stream with `FrameWriter` (`FrameMode::Lines`, `Clock::Unrecorded`, the stream's digest as `source`), `raw`, the trace from `trace::normalise`, the empty tree, then `done` last. The scratch directory is the store's hidden `.import-scratch`, removed when it is empty. A reader failure after detection seals the run `invalid {reader_error}` with the raw kept (R01 error model); an unsupported version seals it `invalid {format_unknown}`; both only after the manifest, raw and tree are written;
     - the manifest has no wall-clock time (`started_at` and `ended_at` are absent), so two ingests of one input are byte-equal, and its import record follows P2. **Branch A (answer "yes, as is"):** `format = claude-code-stream@<reader version>`, `legacy_integrity = {}`, the sources, no requests, and `base_commit` as the recorded answer says. **Branch B (answer "no"):** the new optional origin fields that `contract_wire` added, named in the coordinator's record, with `base_commit` absent; no value is invented.
   - `pub enum RawIngestError` (thiserror, `#[non_exhaustive]`): `NoStream { path }`, `Unreadable { path, detail }`, `Store { detail }`, `Frames { stream, detail }`, `Conflict { run, detail }` (a sealed run whose content the same key disagrees with). It implements `candler_schemas::refusal::Refusal` in `raw.rs` itself. Proposed codes, for the coordinator to confirm: `ingest.no_stream` (side `environment`, path the directory), `ingest.unreadable_path` (side `environment`), and `candler.internal` for the other three, listed in `[internal]`'s allowlist, since an author cannot cause them.
3. `import/mod.rs` gets the one line `pub mod raw;`. No other line moves.
4. A file that calls a unix-only API goes into `platform_inventory.toml`; this one needs none (plain `std::fs`).
**Deliverables**: `crates/candler-core/src/import/raw.rs`: `Found`, `find_streams`, `RawReport`, `ingest_raw`, `RawIngestError`; `crates/candler-core/src/import/mod.rs`: `pub mod raw;`; `docs/contract/codes.toml`: the `[ingest]` rows; `crates/candler/tests/guard_ingest.rs`: the `i1_` guards
**Consistency Checks**: `cargo nextest run -p candler-core -p candler --no-tests=fail -E 'test(/^i1_/)'` (expected: PASS)
**Commit**: `feat(importer): ingest raw claude code trace directories`

## Step 3: The ingest verb
**Goal**: One verb takes raw trace directories and, with `--rules`, results folders, and a results folder behaves as `import` did.
**Implementation Logic**:
1. Write `i2_` and the CLI part of `i1_` first. `i2_a_results_folder_gives_the_mini_corpus_counts` (the mini-corpus through `ingest <corpus> --rules <file>` prints `{"runs": n, "records": n}` with the counts of `crates/candler/tests/guard_cli.rs`'s import row, read from the oracle `crates/candler-core/tests/oracle`, not retyped), `i2_the_old_name_is_an_alias` (`candler import …` equals `candler ingest …`).
2. `commands/ingest.rs`: `IngestArgs { paths: Vec<PathBuf> (at least one), rules: Option<PathBuf> }`. With `--rules`, each path is a results folder: the body of today's `run` runs for each path, unchanged, and the output is one `{"runs": n, "records": n}` line per path (a single path prints exactly today's line). Without `--rules`, each path goes to `ingest_raw` and the verb prints one JSON line `{"runs": n, "created": c, "existing": e, "skipped": [{"path", "reason"}]}` summed over the paths. A results folder given without `--rules` has no stream and is refused with `ingest.no_stream`, and the message says a results folder needs `--rules`. Help texts: `paths` "a raw trace directory, or a results folder when `--rules` is given"; `--rules` ends "cannot be derived: how a legacy folder maps to runs is the importer's input, written by whoever owns the results".
3. The store root is `common::store_root("ingest", cli.store.as_deref())` and `Store::init`, as today; a relative path argument resolves against the caller's working directory (I14), so the binary tests run from an unrelated directory.
4. Errors: `RawIngestError` through `CliError::refused_by` for the two author-facing variants, `CliError::failed("ingest", error)` for the rest; today's rule errors keep their `CliError::refused` text.
5. The ingest never starts a job (R01 calls it a job "for big corpora"; this verb is synchronous, as `import` is).
**Deliverables**: `crates/candler/src/commands/ingest.rs`: `IngestArgs`, `run`; `crates/candler/tests/guard_ingest.rs`: `i1_the_verb_ingests_a_directory`, `i2_a_results_folder_gives_the_mini_corpus_counts`, `i2_the_old_name_is_an_alias`
**Consistency Checks**: `cargo nextest run -p candler --no-tests=fail -E 'test(/^i1_/) | test(/^i2_/)'` (expected: PASS)
**Commit**: `feat(cli)!: ingest raw trace directories and results folders`

## Step 4: Interrupt and resume
**Goal**: An ingest killed at any point and run again leaves the store as one fresh ingest of the same input would, and nothing half-written is a record.
**Implementation Logic**:
1. Write `crates/candler/tests/guard_ingest.rs`'s `i4_` guards first, against Step 3's verb; they may be green at once if Step 2 holds, in which case the bite mutations below are what prove them.
2. `i4_a_killed_ingest_resumes_to_the_fresh_store`: the fixture is a directory of at least 40 streams of about 200 KiB each (generated into a temp dir at test time). The test spawns the binary (`std::process::Command`, its own child, from an unrelated directory), polls `store/runs` until at least one `run.done` exists, then `Child::kill()` (SIGKILL, on a child the test created: no other process is signalled), waits, and asserts non-vacuity: at least one run is sealed and fewer than 40 are. If the child finished first, it grows the fixture and tries again up to three times, then fails: it never passes vacuously. It then ingests again into the same store, ingests the same input into a second fresh store, and compares the two stores' listings: the sorted set of relative file paths under `runs/` (excluding hidden `.tmp-*`, `.replaced` and `.import-scratch` entries) with each file's sha256. They must be equal.
3. `i4_nothing_half_written_is_a_record`: after the kill (same procedure), every directory under `runs/` without `run.done` is not a record: `candler show` and the store's `runs()` ignore it as unfinished, and every sealed run has a parseable `manifest.json` and trace.
4. `i4_an_unsealed_run_is_replaced` (deterministic): a store from a complete ingest, with one run's `run.done` removed by the test (and the run's line left in the index), is repaired by running the ingest again: the run is sealed again with the same key, no duplicate exists, and no `.replaced` directory is left.
5. Bites, applied one at a time to `raw.rs`, each turning a guard red, then reverted: the seal written before the trace; the replicate taken from the number of streams in this call instead of the highest replicate in the store; `Existing::Refuse` in place of `ReplaceUnfinished`.
**Deliverables**: `crates/candler/tests/guard_ingest.rs`: `i4_a_killed_ingest_resumes_to_the_fresh_store`, `i4_nothing_half_written_is_a_record`, `i4_an_unsealed_run_is_replaced`; `crates/candler-core/src/import/raw.rs` (fixes only, if a guard finds a defect)
**Consistency Checks**: `cargo nextest run -p candler --no-tests=fail -E 'test(/^i4_/)'` (expected: PASS)
**Commit**: `test(importer): ingest again after an interruption leaves one store`

## Step 5: The inspect verb
**Goal**: `candler inspect <target>` derives what it can from the target and shows the run, or the job, with outcomes, evidence, provenance and integrity.
**Implementation Logic**:
1. Write the `i3_` guards first (`crates/candler/tests/guard_inspect.rs`, a store seeded as `guard_cli.rs` seeds one, the binary run from an unrelated directory) and see them fail against the scaffold stub: `i3_a_run_directory_needs_no_flag` (the argument is `<store>/runs/<key>`; no `--store`, no environment, the expected store is derived from the path), `i3_a_key_prefix_selects_one_run` (a unique prefix of the key text, at least 6 hex digits; an ambiguous one is refused, listing at most five candidates; a missing one is refused), `i3_a_job_id_shows_its_runs` (the job record's state and the runs whose manifest names the job), `i3_outcomes_come_with_evidence_provenance_and_integrity`, `i3_inspect_writes_nothing`.
2. `commands/inspect.rs`: `InspectArgs { target: String }`, and no other required option. Target resolution, in this order:
   - an existing path holding `manifest.json`: a run directory. Its store root is two levels up (`<root>/runs/<key>`), checked to hold `store.json`; the key is the directory name. `--store` is not read;
   - else a text that parses as a `JobId` and names a directory under `jobs/` of the resolved store: a job;
   - else a hex prefix of a run key in the resolved store (`common::open_store`): `Store::runs()` filtered by `RunKey` display prefix.
3. Run output, one JSON document on stdout: `{"run": key, "sealed": bool, "integrity": {"kind", "reason"?}, "experiment": digest, "job"?: id, "started_at"?, "ended_at"?, "host"?, "import"?: {...}, "provenance": {path: value} (every measured `provenance.*` entry), "measured": {path: value} (every other measured entry), "outcomes": [{"evaluator", "expectation", "role", "status", "value"?, "weight"?, "cause"?, "evidence": [{"ref"?, "note"?}], "request"}]}`, outcomes read with `Store::outcome_files` and `read_outcomes`, in evaluator, expectation and request order, and the latest complete request first per key as `select` orders them. Provenance and measured are open maps (no allowlist).
4. Job output: the job record's `id`, the state as `ps` computes it (reuse its code in `commands/ps.rs`; do not copy it, and do not edit that file), and `runs: [{key, integrity, outcomes: {pass, fail, blocked, not_measured, not_applicable}}]` for the manifests whose `job` is the id.
5. `inspect` opens the store read-only and never recovers a lost job. A target that matches none of the three forms is refused with the three forms listed. The target's help line ends "cannot be derived: it names what to look at".
**Deliverables**: `crates/candler/src/commands/inspect.rs`: `InspectArgs`, `run`, `resolve_target`, `render_run`, `render_job`; `crates/candler/tests/guard_inspect.rs`: the `i3_` guards
**Consistency Checks**: `cargo nextest run -p candler --no-tests=fail -E 'test(/^i3_/)'` (expected: PASS); `! git grep -n 'm3 scaffold' -- crates/candler/src/commands/inspect.rs` (expected: PASS)
**Commit**: `feat(cli): add inspect to show a run with its evidence`
