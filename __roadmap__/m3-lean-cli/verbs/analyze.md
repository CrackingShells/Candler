## Step 1: Choose the evaluator and tally the arms
**Goal**: The library picks one evaluator version, rejects what cannot be analysed with a coded refusal, and builds the arms from `stats`' tally.
**Implementation Logic**:
1. Write the `a1_` and `a3_` guards of `crates/candler-core/tests/guard_analysis_report.rs` first and see them fail. The fabricated store of the guards is a library-level input: a `Selection` built with `OutcomeRecord::builder()`, `RunFacts` and manifests built from JSON as `crates/candler/tests/guard_cli.rs` does (`manifest()`), no store on disk. **The layout** (hand counts; every graded size is in {5, 10}, so each Wilson interval, Fisher p and Newcombe interval is a row of the vector files of `stats`, which is the oracle with the counts):
   - three cells, `A` (`plan.model` = alpha), `B` (beta), `C` (gamma), each with runs 1 to 10 valid; `A` also has run 11 invalid `gateway` and run 12 invalid `killed`, each carrying a `pass` on E1 and E2 that must count nowhere;
   - E1 (gate, default weights): A 6 pass, 2 fail, 2 blocked; B 2 pass, 8 fail; C 5 pass, 5 fail;
   - E2 (gate, default weights): A 3 pass, 2 fail, 3 `not_measured` `{reason: instrument_error}`, 2 `not_measured` `{reason: deadline}`; B 5 fail, 5 `not_applicable` `{reason: not_applicable_to_arm}`; C 5 pass, 5 `not_measured` `{reason: instrument_error}`;
   - E3 (quality): A 8 pass at 5/5 and 2 fail at 2/5; B and C 10 pass at 5/5.
   - Expected: gate sums A 9/15, B 2/15, C 10/15; quality sums A 44/50, B 50/50, C 50/50; E1 and E2 are binary (k and n: A 6/10 and 3/5; B 2/10 and 0/5; C 5/10 and 5/5), E3 is `weighted` in every arm; arm A lists `invalid {gateway: 1}` and `experimenter_ends {killed: 1}`.
2. `analysis/refusal.rs` and its enum `ReportError` (thiserror, `#[non_exhaustive]`), implementing `candler_schemas::refusal::Refusal`, with the codes appended to the `[analysis]` section of `codes.toml`. Proposed, for the coordinator to confirm: `analysis.mixed_evaluator_versions` and `analysis.unknown_evaluator` and `analysis.ambiguous_evaluator_name` (side `suite`: they ask the caller to name one evaluator of the store), `analysis.experiment_unreadable` (side `experiment`, path the file), `analysis.no_outcomes` (side `environment`). A variant not caused by an author (a store read failure) is not in this enum: it travels as `CliError::failed`.
3. `analysis/report.rs`, evaluator choice. `choose_evaluator(selection: &Selection, requested: Option<&str>) -> Result<NameVersion, ReportError>`:
   - the evaluators are the distinct `NameVersion`s among `selection.current()`; none is `no_outcomes`;
   - without a request, exactly one must exist (that is the derivation); several are `mixed_evaluator_versions`, naming each as `name@version`. M3 has no way to ask for a mix, so a mix is always refused (R01: refused unless asked for);
   - with a request, a `name@version` must be one of them (else `unknown_evaluator`); a bare version (the text parses as SemVer and holds no `@`) selects the evaluators that hold that version: exactly one is accepted (quick win 10), none is `unknown_evaluator`, several are `ambiguous_evaluator_name`, naming them.
4. `analysis/report.rs`, arms. `Report::build(input: ReportInput) -> Result<Report, ReportError>` where `ReportInput` holds the selection, the chosen evaluator, `Vec<RunView>` (`RunView { facts: RunFacts, manifest: RunManifest }`, read from the store by the caller) and the declared factors (`Vec<FieldPath>`, possibly empty). It calls `analysis::tally::tally(&selection, &evaluator, &facts)` and keeps, per arm (cell): the tally; the gate and quality `Rate`s; `status` totals (`pass` as `pass + zero_weight`, `fail`, `blocked`, `not_measured`, `not_applicable`), tallied over `gate` and `quality`; each expectation with its `Interval` or its `Omitted` reason; and the I4 violation count of the selection. A cell with no valid run has an entry with zero counts.
5. Per-run rows are an open map, never a fixed struct: `RunRow { run, cell, integrity, comparable: BTreeMap<String, serde_json::Value>, measured: BTreeMap<String, serde_json::Value> }`, filled from every `manifest.comparable().values()` entry that has a value (path to value) and every `manifest.measured()` entry (path to value), with no allowlist, so a path a later milestone records appears with no change here. An `unrecorded` value is left out.
**Deliverables**: `crates/candler-core/src/analysis/report.rs`: `choose_evaluator`, `ReportInput`, `RunView`, `Report`, `Report::build`, `ArmReport`, `RunRow`; `crates/candler-core/src/analysis/refusal.rs`: `ReportError`; `crates/candler-core/src/analysis/mod.rs`: `pub mod report; pub mod refusal;`; `docs/contract/codes.toml`: the `[analysis]` rows; `crates/candler-core/tests/guard_analysis_report.rs`: `a1_arms_equal_the_hand_counts`, `a1_invalid_and_experimenter_runs_are_out_of_k_and_n`, `a1_runs_form_an_open_map`, `a3_one_evaluator_version_is_chosen`, `a3_a_bare_version_needs_a_unique_name`

## Step 2: Compare the pairs of one comparable stratum
**Goal**: Every pair of cells that differ in exactly one declared factor gets the verdict of `stratum_verdict`; a comparable pair gets Fisher, Newcombe and a Holm adjustment over one family per role; a refused pair is reported with its cause and its rates.
**Implementation Logic**:
1. Write the `a2_` guards first and see them fail, plus the Holm-family row of A1. A2 plants **live manifests only**, built as `fixtures/comparability/verdicts.json`'s rows build theirs (read it; never edit it): a stratum differing in a declared factor alone with the clean provenance block (as C52: positive control, comparable); a stratum whose runs carry a different `provenance.eval_infra.commit` (as C48); one that differs in a value no factor declares, `plan.other` (as C03); one with `eval_infra.dirty` true (as C45). A fifth row has two cells that differ in two declared factors: it yields no comparison at all. No row builds or asserts an imported stratum.
2. `analysis/report.rs`, pairs. A stratum is the set of cells whose manifests name one `experiment` digest. The declared factors come from the experiment file whose digest the stratum's manifests name, never from the manifests' own `factors` (a manifest cannot vouch for itself, `compare.rs:160`). `analyze` derives the file: it looks under `<project root>/experiments/` (D9's rule, a small scan in `commands/analyze.rs`, not `ls`'s code) for the file whose `digest_of` equals that digest. `--experiment <file>` names it when it lives elsewhere, stamped "cannot be derived: the file is outside the project's experiments/"; a named file whose digest differs is a refusal (`analysis.experiment_mismatch`). With no file found, `comparisons` is `{"reason": "no_experiment"}` and only arms are reported (coordinator ruling, 2026-11-11). For each unordered pair of cells (key order, `a` before `b`) of a stratum, both with at least one valid run:
   - the differing paths are `analysis`'s call to `manifest::compare::compare(a.comparable, b.comparable)`, and a declared factor *covers* a path through `manifest::compare::covers`; the declared factors that cover at least one differing path are the pair's factors;
   - the pair is a candidate when it has exactly one such factor; a pair with none or with two or more is not a comparison (it is counted in `pairs_not_one_factor`, with no row);
   - the verdict is `stratum_verdict(&views, &declared)` where `views` holds the `ArmView::from_manifest` of every valid run of both cells, in key order. `Comparable` makes a test; `Refused(paths)` is reported `refused` with the paths as its cause; `Malformed(errors)` is `malformed` with their messages. Invalid runs are not in the views: they are not in k and n either.
   - `analysis` calls the verdict and reports its answer; it never reads `claimed_factors`, and it names no imported or live case.
3. For a comparable pair and each expectation graded in both arms: both `ExpectationTally::counts()` must be `Ok` (binary, n of at least 1); otherwise the entry is reported with its `Omitted` reason and takes part in no test. Otherwise Fisher's two-sided p, and `newcombe_difference(a, b)` (the difference is a minus b). A refused pair keeps both arms' rates in `arms` and has no p.
4. Holm: one family per role (`gate`, `quality`) per `analyze` call, made of every tested entry of every comparable pair of that role; its size is reported (`family: {role, m}`). `holm(&p)` is called once per family and each entry gets `p_holm` and `reject = p_holm < ALPHA`. The call carries `alpha: {value, source: "core_default"}` (I12).
5. Output order is deterministic: arms by cell hex, comparisons by `(a, b)`, entries by expectation id.
6. The A1 Holm row uses the layout of Step 1 with `--experiment` declaring `plan.model`: the three pairs (A,B), (A,C), (B,C) are comparable, E1 and E2 give 6 tested gate entries, one family `{gate, 6}`, and E3 is `weighted` in every arm so the quality family is empty. The test recomputes the step-down adjustment from the six raw p-values with its own few lines and compares; the raw p-values and the intervals are the vector rows of `stats`.
**Deliverables**: `crates/candler-core/src/analysis/report.rs`: `Comparison`, `PairVerdict`, `Entry`, `Family`, `compare_pairs`; `crates/candler-core/tests/guard_analysis_report.rs`: `a1_holm_family_is_one_per_role_per_call`, `a2_a_refused_pair_keeps_its_rates_and_cause`, `a2_a_comparable_pair_is_tested`, `a2_only_one_factor_pairs_are_compared`
**Consistency Checks**: `cargo nextest run -p candler-core --no-tests=fail -E 'test(/^a1_/) | test(/^a2_/) | test(/^a3_/)'` (expected: PASS)
**Commit**: `feat(analysis): compare the pairs of one comparable stratum`

## Step 3: The verb
**Goal**: `candler analyze` replaces the scaffold stub, reads the store from any directory and prints the report as JSON or CSV.
**Implementation Logic**:
1. Write the binary guards first, `crates/candler/tests/guard_analyze.rs`, with the Step 1 layout written to a temp store (as `guard_cli.rs` seeds one: `RunWriter`, `OutcomeWriter`, `Store::init`) and the binary run from an unrelated temp directory (I14). Guards `a1_`, `a2_` and `a3_` repeat the library rows through the binary: the JSON equals the hand counts and the vector rows; the planted strata of A2 are refused with their causes; `--evaluator` is refused with the several versions listed, and a bare version is accepted. Seen red against the stub.
2. `commands/analyze.rs`: `AnalyzeArgs` (clap) with:
   - `--evaluator <NAME@VERSION | VERSION>`, optional; help ends "not an experiment setting: names which stored outcomes to analyse";
   - `--experiment <FILE>`, optional; help ends "cannot be derived: the declared factors are in the experiment file, and a manifest cannot vouch for its own"; the file is parsed with `ExperimentFile::from_toml_str` and its `factors()` paths are the declared factors; an unreadable file is `ReportError::ExperimentUnreadable`;
   - `--format json|csv`, default `json`; help ends "not an experiment setting: chooses how the tables are written";
   - `--table arms|comparisons|runs`, default `arms`, read only with `--format csv`; same stamp family.
3. The verb opens the store with `common::open_store`, reads the selection with `common::read_selection`, reads every run's manifest with `Store::runs` and `Store::read_manifest`, builds the `RunView`s, runs `choose_evaluator` and `Report::build`, and writes to stdout. It never writes the store.
4. JSON, one document: `{"evaluator": "name@version", "alpha": {"value": 0.05, "source": "core_default"}, "i4_violations": n, "arms": [{"cell": hex, "runs": {"valid": n, "invalid": {reason: n}, "experimenter_ends": {reason: n}}, "rates": {"gate": {"num", "den"}, "quality": {"num", "den"}}, "status": {...}, "expectations": [{"id", "role", "pass", "fail", "blocked", "not_measured": {cause: n}, "not_applicable": {cause: n}, "zero_weight", "weight": {"num", "den"}, "wilson": {"lo", "hi"} or null, "omitted": "weighted" | "no_runs" | null}]}], "comparisons": [{"a": hex, "b": hex, "factor": path, "stratum": {"verdict": "comparable" | "refused" | "malformed", "causes": [...]}, "entries": [{"id", "role", "a": {"k", "n"}, "b": {"k", "n"}, "p", "p_holm", "reject", "diff", "diff_lo", "diff_hi"} or {"id", "role", "omitted": reason}]}] or {"reason": "no_experiment"}, "families": [{"role", "m"}], "pairs_not_one_factor": n, "runs": [{"run", "cell", "integrity", "comparable": {path: value}, "measured": {path: value}}]}`. Every rate is a `{num, den}` pair, never a bare number (I2); a derived `value` may sit beside it.
5. CSV, one table per call, header first, no quoting beyond RFC 4180: `arms` has one row per (cell, expectation): `cell,role,expectation,pass,fail,blocked,not_measured,not_applicable,zero_weight,num,den,wilson_lo,wilson_hi,omitted`; `comparisons` has one row per (pair, expectation): `a,b,factor,verdict,expectation,role,a_k,a_n,b_k,b_n,p,p_holm,reject,diff,diff_lo,diff_hi,omitted`; `runs` has the fixed columns `run,cell,integrity` followed by one column per path in the union over the rows, sorted, named `comparable.<path>` or `measured.<path>`, empty where a run records none.
6. Errors: a `ReportError` becomes `CliError::refused_by` (the scaffold's constructor); a store read failure is `CliError::failed("analyze", error)`. Exit codes stay 0 and 2 (no change is ever reported, so `Exit::Changed` is not used).
**Deliverables**: `crates/candler/src/commands/analyze.rs`: `AnalyzeArgs`, `run`, `render_json`, `render_csv`; `crates/candler/tests/guard_analyze.rs`: `a1_the_json_equals_the_hand_counts`, `a1_the_csv_tables_equal_the_hand_counts`, `a2_a_refused_pair_is_reported_through_the_binary`, `a3_several_versions_are_refused_through_the_binary`, `a3_a_bare_version_is_accepted_through_the_binary`
**Consistency Checks**: `cargo nextest run -p candler -p candler-core --no-tests=fail -E 'test(/^a1_/) | test(/^a2_/) | test(/^a3_/)'` (expected: PASS); `! git grep -n 'm3 scaffold' -- crates/candler/src/commands/analyze.rs` (expected: PASS)
**Commit**: `feat(cli): add analyze with JSON and CSV output`

## Step 4: The golden corpus
**Goal**: On the real 240-run corpus, `analyze`'s per-cell rates equal the second engine's file, and its status totals equal the oracle's counts.
**Implementation Logic**:
1. `crates/candler/tests/guard_analyze_golden.rs`, `#[ignore]`, reads `CANDLER_GOLDEN_CORPUS` and panics when it is unset, as `guard_golden.rs` does. It imports the corpus with the binary into a temp store (`candler --store <tmp> import "$CANDLER_GOLDEN_CORPUS" --rules crates/candler/tests/fixtures/cli/mini-corpus-rules.toml`, from `CARGO_MANIFEST_DIR`; the rules of the mini-corpus read the golden corpus it was cut from), then runs `candler --store <tmp> analyze --format json` from an unrelated temp directory. The verb name is `import`: the `ingest` leaf keeps it as an alias, so the test holds in either merge order.
2. The test reads `crates/candler/tests/oracle/rates_by_cell.toml` and `counts.toml` with `toml` and no Candler type. It asserts:
   - the 12 cell hexes are the oracle's, and for each, `rates.gate` and `rates.quality` equal `[num, den]` exactly;
   - the sums over cells of `status.pass`, `fail` and `blocked` equal `counts.toml`'s `[imported]` values, and of `zero_weight` equal its `zero_weight`; `not_measured` is 0;
   - at least one expectation of the corpus carries `omitted = "weighted"`, since the oracle's denominators exceed the run count.
   If the status totals disagree with the oracle for a reason the oracle's own README explains (descriptive rows), say so in the report and keep the rate equality; do not edit the oracle.
