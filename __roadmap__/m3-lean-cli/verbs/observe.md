## Step 1: Probe P5, can the gateway check its token for free
**Goal**: Know whether an authenticated check that spends no tokens exists, so that `resolve` gets a gateway step or records a gap.
**Implementation Logic**:
1. Read the gateway's readiness probe, `READY_URL` (`http://127.0.0.1:8080/v1/models`) and `ready_once` in `isolation/gateway.rs`: it asks the sidecar for the model list, which proves the proxy, the injected token and the upstream path, and which answers 401 for a bad token (`NotReadyCause::Unauthorized`). Establish whether that request spends tokens (a model-list read does not on an OpenAI-style endpoint; confirm against the endpoint's documentation).
2. Establish what a check without a sidecar needs: the same `GET /v1/models` from the host, with `Authorization: Bearer` from the secret `model.token_secret` names, against `model.endpoint`. Establish whether the endpoint is reachable from this machine (the real endpoint may need a VPN) and whether a secret is at hand. If either is missing the probe is not run live: say so.
3. The answer, under `## P5` in the leaf report: one of "yes: a host-side model-list read, with these headers and these answers (200 ok, 401 bad token, other unreachable)", "yes, but only through the sidecar, which a preflight must not start", or "no, or not checkable here: gap recorded". Only the first makes Step 2 add `resolve/steps/gateway.rs`.
4. Nothing is committed but the report. Spend no token and send the secret nowhere but the named endpoint.
**Deliverables**: `__reports__/m3-lean-cli/leaves/observe_v0.md`: its `## P5` section
**Consistency Checks**: `grep -q '^## P5' __reports__/m3-lean-cli/leaves/observe_v0.md && git diff --quiet <base> -- crates` (expected: PASS)
**Commit**: `reports(resolve): record whether the gateway token can be checked free`

## Step 2: `candler resolve` and the secrets step
**Goal**: `candler resolve <experiment>` runs the foreground preflight with a secrets step added, prints every resolved value with its source, starts no job and no agent, and reports every failure at once with a check id each.
**Implementation Logic**:
1. Write the guards first and see them red. Each doc carries `Guards:`, `Oracle:`, `Bite:`.
   - `o1_the_secrets_step_derives_presence_and_fails_each_missing_secret` (`candler-core/tests/guard_secrets_step.rs`): three declared secrets, one present: the report has a failed check per missing secret, naming it and never a value, and passes with all present. Bite: a missing secret passing; a value in the explanation.
   - `o1_the_source_printer_names_all_eight_kinds` (`guard_cli_observe.rs`, unit over `render_sources`): hand-built `SourceEntry` values of the eight kinds (`explicit_argument`, `experiment_file`, `project_config`, `user_config`, `derived` with and without `from`, `core_default`, `imported`, `unrecorded`) print eight distinct texts, the `derived` one with its step and its `from`. A live resolution reaches six of them; `imported` and `unrecorded` come only from imported runs, so these two are reached by this unit row alone, reported as a deviation from "all eight reachable". Bite: a kind sharing another's text.
   - `o1_resolve_prints_every_value_with_its_source_and_starts_no_job`: the `cli_run` world, run from an unrelated directory with a `candler.toml` (`store.root`, `plugins.dirs`), a user config (`slots.count`), `--set` on a value, the experiment's own values, a derived value (the fake docker's image id) and a core default (the store root). Each value line has its source; the fake docker's call log has no container create or start; the store has no job directory; the exit is 0. Bite: a value with no source; a job directory written; an agent container created.
   - `o1_resolve_reports_every_failure_at_once_with_codes`: a world with two declared secrets unset and a `plugins.dirs` entry that is not a directory: one run of `candler resolve` prints a line per failure with its check id (`secrets.<name>` style, below) and exits 2, naming at least the two secrets and the directory in the same output. Bite: the verb stopping at the first failure.
2. `candler-core/src/resolve/steps/secrets.rs`: `pub struct SecretsStep` implementing `PreflightStep`, built by `SecretsStep::new(declared: Vec<SecretName>, present: BTreeSet<SecretName>)` (the caller passes `EnvSecrets::new(file.secrets()).present()`, as `run.rs` does for `plan_runs`), and `pub fn register_secret_step(resolver: Resolver, declared: Vec<SecretName>, present: BTreeSet<SecretName>) -> Result<Resolver, ResolveError>`. One `CheckResult` per declared secret, named `secret_<name>` in the check-name grammar, passing when present, with an explanation that names it and never a value. `resolve/steps/mod.rs`: one `pub mod secrets;` line. It does not touch `register_m2b_steps`, `compose_resolver` or `run.rs`: the step runs in `resolve` only, and wiring it into `run` is a follow-up in a file M4 edits. `plan_runs` keeps its check.
3. If P5 said yes: `resolve/steps/gateway.rs`, `GatewayStep`, one check `gateway_token` doing P5's host-side read with a short timeout: 200 passes, 401 fails with "the token was refused", an unreachable endpoint fails with "unreachable", and no token is spent. Registered beside the secrets step. If P5 said no, the step does not exist and the leaf report names the gap.
4. `commands/resolve.rs`, replacing the stub: `Args { experiment: PathBuf, fields: Vec<(FieldPath, String)> (--set, as `run`), json: bool (--json) }`. Read the experiment as `run` does, `request_settings` and `foreground` from `commands/preflight.rs`, register the secrets step (and the gateway step), resolve. The text form prints one line per value and per setting, sorted by path: `<path>\t<value as JSON>\t<source>`; `--json` prints the `Resolution` document. A resolution error is printed whole: a `ResolveError::Preflight` lists every failed report and every step error, with the check id `<step name>.<check name>` per failed check and `<step name>.error` per step error (not the five-and-`more` of its `Display`), then the checks of the verb itself: each entry of `plugins.dirs` that is not a directory fails as `plugins.dir_missing`. All of them are collected before any exit; the exit is 2. These ids are check ids, not the codes of `docs/contract/codes.toml`: that registry belongs to `refusal_core`, and whether `resolve` also gets a section is a question for the coordinator.
5. No agent and no job: the verb never calls `ensure_sidecar`, `plan_job`, `JobDir::create` or `detach`. It builds the image through the same preflight step as `run` does, which is what "real" means here.
**Deliverables**: `crates/candler-core/src/resolve/steps/secrets.rs`: `SecretsStep`, `SecretsStep::new`, `register_secret_step`; `crates/candler-core/src/resolve/steps/mod.rs`: `pub mod secrets` (and `pub mod gateway` with `GatewayStep` only if P5 says yes); `crates/candler/src/commands/resolve.rs`: `Args`, `run`, `render_sources`, `render_failures`; `crates/candler-core/tests/guard_secrets_step.rs`: `o1_the_secrets_step_derives_presence_and_fails_each_missing_secret`; `crates/candler/tests/guard_cli_observe.rs`: the three other `o1_` guards

## Step 3: `candler ls`
**Goal**: `candler ls [PATH...]` lists the experiment files under `<project root>/experiments/` recursively, plus every path given, each with its declared cells and the stored runs that match it, and lists any other TOML file as skipped with its reason.
**Implementation Logic**:
1. Write the guards first on a fixture tree under `tests/fixtures/observe/ls/` (`candler.toml`; `experiments/a.toml` and `experiments/sub/b.toml` valid `experiment/1`; `experiments/notes.toml` not an experiment; `elsewhere/c.toml` valid; `other/d.toml` valid and outside `experiments/`) and see them red.
   - `o2_ls_lists_experiments_under_experiments_and_the_paths_given`: from an unrelated directory with the project found by `candler.toml`: `ls` lists `a` and `b` and not `c` or `d`; `ls elsewhere` adds `c`; a path that is a file lists that file. Each line has the path, the number of declared cells (`ExperimentFile::cells().len()`) and the stored runs. Bite: a scan of the whole project (it finds `d`); a scan of the working directory.
   - `o2_ls_skips_other_toml_with_its_reason_and_never_scans_the_cwd`: `notes.toml` is listed as `skipped` with the parse reason; with no project, `ls` looks at `./experiments/` of the working directory and nothing else; a missing `experiments/` is an empty listing and exit 0. Bite: the skipped file dropped; the reason lost.
2. `commands/ls.rs`, replacing the stub: `Args { paths: Vec<PathBuf> }`. Roots are `<project root>/experiments/` (the project from `Config::load`, else `<cwd>/experiments/`) and each given path, made absolute against the working directory (I14). Walk directories recursively for `*.toml`, in sorted order, skipping nothing silently: a file that does not read as `experiment/1` (`ExperimentFile::from_toml_str`) is a `skipped` line with the error's text. Never follow a symlink out of a root.
3. Stored runs: a run counts for a file when every value the file declares (`[fixed]` and each factor level of a cell) equals the run's recorded `comparable` value at that path, read through `RunManifest::comparable()`; the store is the one `common::store_root` finds, and no store is an empty count, not an error. Why a match by declared values: the experiment digest the manifest records needs a preflight (derived values), which `ls` does not run. This is the leaf's choice and goes in the report, with the case it cannot tell apart (two files declaring the same values). If `Comparable` does not expose its values by path, report it and show the cell count only.
**Deliverables**: `crates/candler/src/commands/ls.rs`: `Args`, `run`, `list_roots`, `Listing`; `crates/candler/tests/fixtures/observe/ls/**`; `crates/candler/tests/guard_cli_observe.rs`: `o2_ls_lists_experiments_under_experiments_and_the_paths_given`, `o2_ls_skips_other_toml_with_its_reason_and_never_scans_the_cwd`

## Step 4: Terminal rules, and `watch` that defaults to JSON
**Goal**: One rule decides colour for every verb, `watch` prints JSON lines with no flag, and `watch --live` shows progress: redrawn on a terminal, plain lines on a pipe.
**Implementation Logic**:
1. Write the guards first and see them red.
   - `o3_color_is_on_only_on_a_terminal_with_no_color_unset` (unit, `commands/term.rs` through its public function): the four rows of (terminal or not) × (`NO_COLOR` unset, set to a value, set empty). Colour only for a terminal with `NO_COLOR` unset or empty (no-color.org: a non-empty value disables). Bite: colour on a pipe; `NO_COLOR` ignored.
   - `o3_watch_prints_json_lines_by_default` (`guard_cli_observe.rs`): over a job directory built from a recorded event log in `tests/fixtures/observe/events.jsonl`, `watch <id>` with no flag prints each event as one JSON line, as `watch --json` did, and `--json` is still accepted. Bite: the refusal "watch needs --json" kept.
   - `o3_live_on_a_pipe_prints_plain_lines_and_no_escape_byte`: the same job, `watch <id> --live` with stdout and stderr piped, `NO_COLOR` unset then set: the output is plain progress lines (`progress runs <ended>/<started> outcomes <n>`, one per change) and holds no 0x1b byte anywhere. `--live` and `--json` together are refused by clap. Bite: ANSI on a pipe.
2. `commands/term.rs`: `pub fn color_enabled(stdout_is_terminal: bool, no_color: Option<&std::ffi::OsStr>) -> bool` (pure), `pub fn stdout_color() -> bool` (reads `std::io::IsTerminal` on stdout and the `NO_COLOR` variable), and `pub struct Paint { on: bool }` with `Paint::new(on)` and the few methods the verbs use (`bold`, `dim`, `red`, `green`), each returning the text unchanged when `on` is false. There is no `--no-color` flag (R10 D10).
3. `commands/watch.rs`: `Args.json` stays as an accepted flag; `--live` is added and conflicts with it. `follow` no longer refuses without `--json`; without `--live` it prints JSON lines. With `--live`, after each batch of events it computes the progress from the events seen so far (`run.started` / `run.ended` / `run.failed` runs, and `evaluation.outcome` count) and, on a terminal, rewrites one line with `\r` and `Paint`; on a pipe it prints a plain line only when the progress changed. The poll, the recovery of a lost job and the end are as today. The `Paint` is the only place an escape byte is written.
**Deliverables**: `crates/candler/src/commands/term.rs`: `color_enabled`, `stdout_color`, `Paint`; `crates/candler/src/commands/watch.rs`: `Args::{json, live}`, `follow` with the default and the progress line; `crates/candler/tests/fixtures/observe/events.jsonl`; `crates/candler/tests/guard_cli_observe.rs`: `o3_color_is_on_only_on_a_terminal_with_no_color_unset`, `o3_watch_prints_json_lines_by_default`, `o3_live_on_a_pipe_prints_plain_lines_and_no_escape_byte`

## Step 5: `ps` shows what each job runs
**Goal**: Each `ps` row ends with the experiment or the suite of its job, read from the job's spec, which the supervisor now keeps in the job directory.
**Implementation Logic**:
1. Write the guard first and see it red: `o3_ps_shows_the_experiment_or_the_suite` (`guard_cli_observe.rs`): two job directories built by the test, one with a run spec and one with an evaluate spec written as `spec.json`, and one without it. `ps` prints each row's four existing fields unchanged and a fifth, last field with no space: `experiment:<12 hex of the experiment digest>`, `suite:<file name>`, and `-` when the job has no spec file. Bite: a row with no fifth field; the four earlier fields moved (the existing `split_whitespace` guards read them by position).
   Then `o3_spec_file_holds_no_secret_value` (`crates/candler-core/tests/guard_spec_file.rs`, new, so no L1 sibling shares the file; through the real supervisor and the test harness): a job whose experiment names a secret whose value is present in the caller's environment as a planted, unique string; once the job has started, `<job dir>/spec.json` exists and its bytes do not contain that string, while its secret appears by name only. Bite: writing the resolved environment, or a `secrets` map with values, into the file. At a26fe53 a spec holds secret names and presences only (`SecretName`, `SecretPresence`); the guard keeps it so (coordinator condition, 2026-11-11).
2. The defect this step answers: the plan has `ps` read `JobSpecFile`, but the job directory keeps no spec. The launcher sends it on the supervisor's stdin and `job.json` keeps only its digest. So `jobs/runtime/session.rs`, in the one function that reads the spec and checks its digest, writes the verified bytes to `<job dir>/spec.json` with `write_atomic` (`pub const SPEC_FILE: &str = "spec.json"` beside `RECORD_FILE`). The hunk is three lines, in that one function and nowhere else of `jobs/runtime/`, and it is listed in `m3-overlap-for-m4.md`: M4's `harness_out_of_core` edits the same module, and the milestone that merges second resolves the conflict (coordinator ruling, 2026-11-11). A job started before this change, or still starting, has no file and reads `-`.
3. `commands/ps.rs`: `Row` gains `what: String`, printed last by `render_rows`. `row_of` reads `SPEC_FILE`, parses a `JobSpecFile`, and takes `experiment:` and the first 12 hex of `experiment_of(&spec.experiment, &spec.resolution)` for a run spec, `suite:` and the file name of `EvaluateSpec.suite` for an evaluate spec; any error is `-`. Whitespace in a file name becomes `_`.
**Deliverables**: `crates/candler-core/src/jobs/runtime/session.rs`: `SPEC_FILE`, the write in the spec reader; `crates/candler/src/commands/ps.rs`: `Row::what`, `row_of`, `render_rows`; `crates/candler/tests/guard_cli_observe.rs`: `o3_ps_shows_the_experiment_or_the_suite`; `crates/candler-core/tests/guard_spec_file.rs`: `o3_spec_file_holds_no_secret_value`
