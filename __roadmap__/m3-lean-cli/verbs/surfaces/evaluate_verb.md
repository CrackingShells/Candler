## Step 1: The hidden verb supervises an evaluate job
**Goal**: `candler supervise --job <id>` reads a `JobSpecFile` and runs the evaluate body for an `Evaluate` spec, with no Claude driver and no skill tree built for it.
**Implementation Logic**:
1. Write the guard first, in the new `tests/guard_cli_evaluate.rs`, and see it red: `e1_supervise_runs_an_evaluate_spec_written_by_hand`. It builds the world of `support/cli_run.rs` and the `pool` plug-in directory as `guard_cli.rs`'s `plugin_of` builds one (from `plugin_pool.toml` and `kinds/engine_pool.py`), imports nothing, seals one run with `candler run`, writes an `Evaluate` spec file for that run by hand, creates the job directory with `JobDir::create` and a `job.json` whose digest is the spec's, and starts `candler supervise --job <id>` with the spec on stdin and the environment `evaluate` will give it. It waits for the lock to be free. Oracle: the job's `events.jsonl` ends in `job.ended(completed)`, `report.json` exists, and the store holds an outcome file per graded run. Bite: the arm missing (the verb builds the Claude driver and reads the spec as a `JobSpec`, which an `Evaluate` file is not).
2. `commands/supervise.rs`: read the spec through the scaffold's boundary reader (`JobSpecFile`). The `Run` arm is today's body unchanged (`ClaudeCodeDriver`, `ClaudeSkills`, `JobEntry`, `orchestrate`). The `Evaluate` arm builds an `EvaluateEntry { store, job, spec }` and awaits `supervise_evaluate`; it builds no driver. The identity write (`dir.set_supervisor(own_identity())`) happens before the split, as now.
3. This file is also M4's (`commands/supervise.rs`): the edit is one `match`, so a second-to-merge rebase is a hunk, and the coordinator is told.
**Deliverables**: `crates/candler/src/commands/supervise.rs`: the dispatch on `JobSpecFile`, `run` with an `Evaluate` arm; `crates/candler/tests/guard_cli_evaluate.rs`: `e1_supervise_runs_an_evaluate_spec_written_by_hand`

## Step 2: `evaluate <suite>` starts the job, prints its id and the report
**Goal**: The verb resolves the plug-ins from `plugins.dirs`, writes the evaluate job and starts its supervisor, prints the job id on stderr, follows the job to its end and prints the report on stdout, with the old options gone and every caller migrated.
**Implementation Logic**:
1. Write the guards first, in `tests/guard_cli_evaluate.rs`, and see them red. Each doc carries `Guards:`, `Oracle:`, `Bite:`.
   - `e4_evaluate_with_no_plugin_option_grades_exactly_the_runs_just_run`: the `cli_run` world, the `pool` plug-in directory, a project directory `<root>/project` holding a `candler.toml` with `[plugins] dirs = ["../plugin"]`, the helper's environment built under the world's state home (`seam::sync_environment`), a fresh `candler run`, then `candler evaluate <suite_pool_ok.toml>` run from `project/`. Rows: (1) the report's `failed_requests` is empty and the store holds an outcome file for exactly the run keys the fake docker was handed (`run_keys(&world.calls())`) and no other; (2) a second `evaluate` of the same suite writes no new outcome file and its counts are empty (`Pending` finds every run complete); (3) `evaluate <suite> <job-id>` with the id of the run job grades that job's runs, and `evaluate <suite> --runs '<glob>'` grades the runs the glob names; the two forms together are refused by clap, exit 2. Bite: the selection is every run (row 2 grades again) or none (row 1 finds no file).
   - `e1_evaluate_prints_the_job_id_on_stderr_and_the_report_on_stdout`: stderr's first line parses as a `JobId`; stdout is one JSON document with `request_ids`, `counts`, `outcome_files` and `failed_requests` and nothing else; the job directory's `events.jsonl` holds one `evaluation.outcome` per record the store's outcome files hold, then `job.ended` with `completed` as its last line, and `candler ps` shows the job `ended`. Bite: the id on stdout; the report printed while the job has ended `failed`.
   - `e1_evaluate_refuses_without_a_plugin_directory`: no `plugins.dirs` anywhere → exit 2, a refusal naming `plugins.dirs`, no job directory created. Bite: the job started and failing later.
2. `commands/evaluate.rs`, the arguments: `EvaluateArgs { suite: PathBuf, job: Option<JobId> (positional, conflicts with --runs), runs: Option<String> (--runs <glob>, conflicts with the job) }`. `--plugin`, `--suite` and `--concurrency` are deleted, with the `NonZeroUsize` import.
3. The flow of `run(cli, args)`:
   - load the configuration (`common::load_config`); the plug-in directories are `config.project.plugin_dirs` (absolute), refused when empty. `discover_manifests` and `Registry::load` give the registry; `default_env_root` gives the environment root; `common::evaluation_resolver` with a supervisor over `common::StderrSink` runs the preflight in the foreground, which builds the plug-in environments, as today; `common::resolved_root` gives the store.
   - make the suite path absolute against the working directory and read its bytes for `suite_digest`.
   - the selection: `<job-id>` reads that job's `events.jsonl` (`JobEvents::tail`) and keeps the run keys of its `run.started` events, refusing a job that started none, as `RunSelection::Keys`; `--runs` is `Glob`; neither is `Pending`.
   - write the job: `EvaluateSpec` in `JobSpecFile::Evaluate`, its bytes, `spec_digest`, `mint_job_id`, a `JobRecord` as `run.rs`'s `start` builds it, `JobDir::create`, then `detach(DetachArgs)` with the environment `PATH`, `HOME`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME` and `STORE_ENV` (`commands::run::STORE_ENV`). `XDG_CONFIG_HOME` is in the list because the supervisor reads `slots.evaluators` from the user configuration; `run.rs`'s allowlist has no `XDG_CONFIG_HOME`, which is reported to the coordinator as an existing defect of `run` and left alone.
   - print the job id on stderr (`eprintln!`), then follow: poll `JobEvents::tail` and `lost::classify` every 200 ms until the job is `Ended`; a `Lost` job is recovered with `recover_job_dir`, as `watch::follow` does. `watch.rs` is not reused: `observe` owns it and changes its signature. Nothing is printed to stdout while following.
   - at the end read `report.json` (`jobs::runtime::evaluate::REPORT_FILE`) and print it on stdout. An end of `failed` is `CliError::Failed` with the last lines of the job's `supervisor.log`; a failed request in the report is `CliError::Runtime("`evaluate`: N request(s) failed")`, exit 2, as today.
4. Migrate the callers, in this commit, because the options go away here:
   - `tests/support/seam.rs::evaluate(world, manifest)`: it runs from a project directory holding a `candler.toml` with `plugins.dirs` naming the manifest's directory, and passes the suite as the positional argument. `guard_input_seam.rs` parses stdout as before and is not edited.
   - `tests/guard_cli.rs`, `evaluate_diff_and_show_over_two_plugin_versions_follow_the_fixture_verdicts`: each version runs `evaluate <suite> --runs "*-r6-a1"` from its own project directory whose `candler.toml` names `plugin-<version>`; the `candler` helper is not edited (a new helper takes the working directory). The G-text exception is exactly these argument lines.
   - `tests/guard_golden_parity.rs`: the two regrades run `evaluate <suite> --runs '*'` from a project directory whose `candler.toml` names the manifest's directory (`plugin_project/..`, where `candler-plugin.toml` is), with `slots.evaluators = 8` in the user configuration in place of `--concurrency 8` (check `run_candler`'s `XDG_CONFIG_HOME`). `--runs '*'` is needed because the default selection grades only pending runs and the second regrade must grade all of them again. It is ignored without the corpus: it is checked by building, and run when `CANDLER_HTN_PLUGIN` is set.
5. The migration, for the commit body: `evaluate --plugin M --suite S [--runs G] [--concurrency N]` becomes `evaluate S [--runs G]` run in a project whose `candler.toml` lists the directory of `M` under `plugins.dirs`; `--concurrency N` becomes `slots.evaluators = N` in the user configuration; a selection that grades every run, as the old default did, is `--runs '*'`.
**Deliverables**: `crates/candler/src/commands/evaluate.rs`: `EvaluateArgs { suite, job, runs }`, `run`; `crates/candler/tests/guard_cli_evaluate.rs`: `e4_evaluate_with_no_plugin_option_grades_exactly_the_runs_just_run`, `e1_evaluate_prints_the_job_id_on_stderr_and_the_report_on_stdout`, `e1_evaluate_refuses_without_a_plugin_directory`; `crates/candler/tests/support/seam.rs`: `evaluate`; `crates/candler/tests/guard_cli.rs` and `crates/candler/tests/guard_golden_parity.rs`: the migrated `evaluate` calls

**Commit**: `feat(cli)!: start evaluate as a job and follow it to its report`

## Step 3: Ctrl-C ends the job
**Goal**: Ctrl-C on the waiting command stops the evaluate job through the guarded `kill` path and leaves it `killed`, with no process of it alive, and every other way the job can end gets its own exit.
**Implementation Logic**:
1. Write the guard first in `tests/guard_cli_evaluate.rs` and see it red: `e1_ctrl_c_ends_the_evaluate_job_killed`. The `pool` plug-in's `interval` kind with `sleep_s` set to 60 keeps a request in flight; the test starts `candler evaluate` as a child it owns, waits for the plug-in's `start` line, sends SIGINT to that child through `rustix::process::kill_process` (a pid the test spawned; no `kill` command), and waits. Oracle: the command exits 2 within `TEARDOWN_BOUND` and says it was cancelled; the job's last event is `job.ended` with `killed`; the lock is free; the evaluator's pid from the plug-in's file is gone with its start time. Bite: the job left running (the command exits, the lock stays held).
2. `commands/evaluate.rs`: race the follow loop against `tokio::signal::ctrl_c()`. On Ctrl-C call `commands::kill::stop_job(&StoreLayout::new(&root), &id)` (its reap of the supervisor goes through the I22 guard; no signal is sent from here), then keep following until the job ends, bounded by `TEARDOWN_BOUND`.
3. The end decides the exit, whatever raced it: an end of `killed` after Ctrl-C is `CliError::Runtime("`evaluate` was cancelled")`, exit 2, and no report; an end of `completed` that won the race prints the report and exits by its failed requests; an end of `killed` with no Ctrl-C (someone ran `candler kill`) is `CliError::Runtime("`evaluate` was killed")`. A second Ctrl-C is not handled: the default action ends the waiting command and the job stays stopped.
**Deliverables**: `crates/candler/src/commands/evaluate.rs`: the Ctrl-C arm and the end mapping; `crates/candler/tests/guard_cli_evaluate.rs`: `e1_ctrl_c_ends_the_evaluate_job_killed`
**Consistency Checks**: `cargo nextest run -p candler --no-tests=fail -E 'test(/^e1_/) | test(/^e4_/)'` (expected: PASS)
**Commit**: `feat(cli): stop the evaluate job when the command is interrupted`
