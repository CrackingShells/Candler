## Step 2: Detect and parse stream-json lines
**Goal**: The reader recognises a supported stream and turns each line into events, keeping unknown lines.
**Implementation Logic**:
1. `ClaudeCodeReader::new() -> ClaudeCodeReader` implementing `TraceReader` with `framing() = Lines` and `id() = READER`; `READER: NameVersion` (`claude-code-stream-json@<reader version>`), the version bumped whenever output changes; `SUPPORTED`: `>=2.1.220, <2.2.0`.
2. `detect(sample)`: the first JSON line is `type: system`, `subtype: init` with a `claude_code_version` in `SUPPORTED` → `Some((version, Certain))`; anything else → `None`.
3. `feed(FrameIn)`: one JSON line → events: `user` and `assistant` messages, `tool_use` blocks → `tool_call` (`span` = the `tool_use` id; `mcp__<server>__<tool>` → `origin: mcp {server}`), `tool_result` blocks → `tool_result`, `system` lines other than init and every unknown `type` → `notification` with the line in `ext`. `raw_ref` is `FrameIn.raw_ref`; `at` from the line's `timestamp` when present, else `FrameIn.at`, else absent; never interpolated. A blank frame yields nothing; a line that is not JSON → `notification` with the text in `ext`.
**Deliverables**: `crates/candler-harness-claude-code/src/{lib.rs,detect.rs,parse.rs}` (`ClaudeCodeReader`, `READER`, `SUPPORTED`)
**Consistency Checks**: `cargo clippy -p candler-harness-claude-code --all-targets -- -D warnings` (expected: PASS)
**Commit**: `feat(adapter-claude-code): detect and parse stream-json lines`

## Step 3: Normalise sessions, subagents and denials
**Goal**: Sessions, subagent sessions, denials, usage and `ended_by` follow R01's rules.
**Implementation Logic**:
1. One root session per `session_id`: further init and result lines with the same id continue it. A line with a `parent_tool_use_id` belongs to the child session `<root id>/<parent_tool_use_id>` (`SessionId::child`), declared before its first event.
2. Usage: the first line carrying a `message.id` emits `usage {scope: message}` from its `message.usage`; later lines with the same id emit none. A result line emits `usage {scope: session_total}` with `total_cost_usd`, as the session's running total (D2): from the streams with several result lines, `expected.toml` states whether Claude Code reports per turn or running, and the reader sums per-turn reports before emitting.
3. Denials: an entry of a result's `permission_denials[]` marks the `tool_result` with the same `tool_use_id` `denied {by: harness}`.
4. `ended_by` from the session's last result line: `subtype: success` and `is_error: false` → `completed`; a non-null `api_error_status` → `gateway_error`; `is_error: true` otherwise → `agent_error`, with `reason` from `terminal_reason`, else `subtype` (so the `api_error` run is `agent_error`); `error_max_turns` → `cap {turns}`; no result line → `unknown`. Child sessions end `completed` when their parent's call has a result, else `unknown`.
5. `observed()` lists the root session ids seen so far; `finish` returns the sessions root first, each parent before its children.
**Deliverables**: `crates/candler-harness-claude-code/src/{sessions.rs,usage.rs}`
**Consistency Checks**: `cargo clippy -p candler-harness-claude-code --all-targets -- -D warnings` (expected: PASS)
**Commit**: `feat(adapter-claude-code): normalise sessions, subagents and denials`

## Step 4: Pin normalised output to the reader version
**Goal**: The reader meets every expected fact, and its output is pinned so a change needs a version bump.
**Implementation Logic**:
1. `tests/guard_reader.rs`: the six B tests of the Success Gates. Expected values come only from `expected.toml`, `usage_totals.toml` and hand-written literals.
2. `tests/fixtures/digests.toml`: stream name → sha256 of the trace file, with the reader version in its header; blessed with `CANDLER_BLESS_DIGESTS=1`, which refuses to rewrite an existing line unless `READER`'s version changed.
3. Then delete the leaf's scaffolding and write the bite record.
