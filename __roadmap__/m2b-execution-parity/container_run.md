## Step 1: Mounts and the mount-escape refusal
**Goal**: A mount list is built only from canonical paths inside the project root or the store.
**Implementation Logic**:
1. `mounts.rs`: `pub struct MountSpec { source: PathBuf, target: PathBuf, mode: MountMode }` with `MountMode::{ReadOnly, ReadWrite}`; `pub fn mounts(plan: &ContainerPlan, roots: &MountRoots) -> Result<Vec<MountSpec>, MountError>`, where `MountRoots { project: PathBuf, store: PathBuf }` come from the plan. Inputs are read-only, workspace, HOME (or `CLAUDE_CONFIG_DIR`) and the run output dir are read-write. R05b: `claude -p` over a read-only HOME exits 0 and persists nothing, so the writable config dir is deliberate and the runner must see transcripts appear; a mount list with no writable config dir is `MountError::ConfigDirNotWritable`.
2. R23: `std::fs::canonicalize` every source (run it in `spawn_blocking` when called from async). Refuse, with the offending path in the variant: outside both roots (`MountError::OutsideRoots`), a symlink whose target leaves the roots (`MountError::SymlinkEscape`, detected by comparing the lexical and canonical paths), and any path whose components name `docker.sock` or that sits under `/var/run` or `/run` (`MountError::DockerSocket`). Check the canonical path, so `/tmp/x -> /var/run/docker.sock` is refused as well.
3. The `--mount type=bind,source=..,target=..[,readonly]` text comes from `MountSpec::to_arg`, which refuses a comma or newline in a path (`MountError::BadPath`): a comma would inject another `--mount` option.
4. Class A, in `#[cfg(test)] mod scaffold`: a table of literal path cases on a `tempfile` tree (inside, outside, symlink out, symlink in, `docker.sock` name, `/run` prefix, comma in a name) with literal expected variants.
**Deliverables**: `crates/candler-core/src/isolation/container/mounts.rs` (`MountSpec`, `MountMode`, `MountRoots`, `mounts`, `MountError`, `MountSpec::to_arg`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::container::mounts/)'` (expected: PASS)
**Commit**: `feat(isolation): build container mounts only from canonical roots`

## Step 2: The docker run argv
**Goal**: One pure function yields the hardened, labelled argv, and refuses secrets (R15).
**Implementation Logic**:
1. `run.rs`: `pub fn run_argv(plan: &ContainerPlan, cmd: &CommandSpec) -> Result<Vec<String>, RunArgvError>` (R12: a free function, owned here). The order is fixed: `docker run`, then the hardening flags, then labels, then env, then mounts, then `--`-free image ID, then the wrapped command.
2. Hardening, on every agent container: `--init`, `--read-only`, `--tmpfs /tmp:rw,noexec,nosuid,size=<n>m`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--pids-limit <n>`, `--memory <n>`, `--cpus <n>`, `--network <per-job network>` from the `GatewayHandle`, `--user <uid>:<gid>` on a Linux engine only (Docker Desktop maps ownership itself; B09 is Linux only), `--cidfile <path in the job's children dir>`, and never `--rm` (the supervisor must still read the exit and the guard destroys). Limits come from the plan with a default, never from the cmd.
3. Labels: `candler.job=<job>`, `candler.run=<run key>`, `candler.experiment=<id>`, `candler.role=agent`. Control containers (R11) use a different function `control_argv(..)` in the same file: `--rm`, `candler.role=control`, `candler.job=preflight`, the same hardening, never destroyable by the guard.
4. Env, built from nothing (README, Docker practice): only `PATH`, `HOME`, `VIRTUAL_ENV`, `LANG`, and the overlay entries. The overlay passes through `fn env_args(overlay: &EnvOverlay) -> Result<Vec<String>, RunArgvError>`: any `EnvValue::Secret` is `RunArgvError::SecretRefused`; the names `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` in the overlay are `RunArgvError::ReservedName(name)` (R15). The wrapper then sets the base URL (the gateway's in-network address from `GatewayHandle`) and the dummy token itself. The dummy token is a constant that opens nothing off the sidecar.
5. Values go in as `-e NAME=value` only for plain values. No host env passes through (`--env-file` is out).
6. Class A: golden argv vectors for the HTN-shaped plan, with literal expected vectors. B07 lands in Step 5.
**Deliverables**: `crates/candler-core/src/isolation/container/run.rs` (`run_argv`, `control_argv`, `env_args`, `RunArgvError`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::container::run/)'` (expected: PASS)
**Commit**: `feat(isolation): build the hardened docker run argv`

## Step 3: Self-expiry and the SpawnRequest
**Goal**: The container kills itself when the supervisor cannot, and the request carries the right marker and hook point.
**Implementation Logic**:
1. `expiry.rs`: `pub fn wrap_expiry(cmd: &CommandSpec, secs: u64) -> CommandSpec` prefixes coreutils `timeout --signal=TERM --kill-after=10 <secs>`. R3: debian-slim, so exit 124 on expiry. R4: the inner timeout is `wall_s + EXPIRY_MARGIN` and the supervisor deadline is `wall_s`, so the supervisor times out first, destroys through the guard, and the inner timeout is the net if the supervisor dies. `EXPIRY_MARGIN` is a `layout.rs` constant: read it in code, but tests pass a literal margin and never import it.
2. `run.rs`: `pub fn build_run_request(plan: &ContainerPlan, cmd: CommandSpec, marker: Marker, key: RunKey) -> Result<SpawnRequest, RunArgvError>` is the free function that `Isolation::run_request` delegates to; it calls `wrap_expiry(cmd, plan.expiry)` (`plan.expiry` is the per-run wall plus the margin, set by the planner), then `run_argv`, then `SpawnRequestBuilder` with the docker client binary and the client env allowlist (`DOCKER_HOST`, `DOCKER_CONTEXT`, `HOME/.docker`, nothing else), the marker, the run key and the wall time as the supervisor deadline. It never calls `stop_hook`: R7 puts that on the `DockerIsolation` level so that the hook attaches per request. Mount roots come from `ContainerPlan.project_root` and `ContainerPlan.store_root` (A3), never from the cwd or the environment.
3. `DockerIsolation::new(gateway: GatewayHandle, docker: Arc<dyn DockerDriver>, guard: Arc<ContainerGuard>)` (A2) holds the job's gateway handle, the driver and the guard, and holds no plan and no hook; `impl Isolation` (A1): `plan(&self, &Cell<'_>, &Workspace<'_>) -> Result<ContainerPlan, IsolationError>`; `run_request(&self, &ContainerPlan, CommandSpec, Marker, RunKey) -> Result<IsolatedRequest, IsolationError>`, which calls `build_run_request` with the run's own gateway base URL (`GatewayHandle::run_base_url(&RunKey)`, A5), builds one fresh `ContainerStopHook` for that request with container_stop's `ContainerStopHook::new(guard, sweeper, job)` (a `LabelSweeper`, and the job from `plan.labels`), attaches it with `SpawnRequestBuilder::stop_hook` and returns `IsolatedRequest { request, end_facts }`, where `end_facts` is the same `Arc<ContainerStopHook>` coerced to `Arc<dyn EndFacts>` (container_stop writes that impl); and `collect_and_destroy<'a>(&'a self, &'a ContainerPlan, &'a Workspace<'a>, &'a Exit) -> BoxFuture<'a, Result<ContainerOutcome, IsolationError>>`. There are no `prepare` and no `wrap` methods. All async methods return `BoxFuture<'a, ..>` bound to `&'a self` and to every borrowed argument (round 3, N1), not `'static`. `collect_and_destroy` and any method that touches the guard are container_stop's; this leaf leaves them delegating to the hook with the signature the scaffold gives.
4. Class A: the wrapped command's literal vector, plus a table of wall, margin and the expected `timeout` seconds.
**Deliverables**: `crates/candler-core/src/isolation/container/expiry.rs` (`wrap_expiry`); `crates/candler-core/src/isolation/container/run.rs` (`build_run_request`); `crates/candler-core/src/isolation/container/mod.rs` (`DockerIsolation`, `ContainerPlan` use only)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::container/)' && cargo clippy -p candler-core --all-targets -- -D warnings` (expected: PASS)
**Commit**: `feat(isolation): wrap agent commands in a self-expiring timeout`

## Step 4: Real-container tests B06, B08, B09
**Goal**: The kernel confirms what the argv claims.
**Implementation Logic**:
1. The tests are `#[path]` modules in a file the S3 harness `tests/guard_container_e2e.rs` includes (this leaf does not edit the harness). Each drives the real docker CLI through an `AllowlistDriver` that panics on any container id the test did not create, asserts only on `candler.job=<test id>`, and is cleaned up by the test's own `ContainerGuard` over the recording-free real driver in the allowlist wrapper. No test runs `kill`, `pkill`, `docker rm -f $(...)` or a prune.
2. `b06_kernel_facts`. `/// Guards: B06 — the argv hardening holds in the kernel.` `/// Oracle: the testagent probe JSON.` `/// Bite: drop --cap-drop ALL.` Run `probe` with an input mount, a workspace, HOME and tmp; assert euid not 0, `CapEff` is `0000000000000000`, `NoNewPrivs` 1, EROFS writing `/` and the input mount, success writing workspace, HOME and tmp, and the host sentinel path (created in the test tmpdir, never mounted) absent. Literal expected values, provenance comment citing the kernel doc.
3. `b08_self_expiry`. `/// Guards: B08 — the inner timeout expires a container the supervisor does not stop.` `/// Oracle: exit code 124 of docker run on the real debian-slim base.` `/// Bite: remove the timeout wrapper.` `sleep-forever`, wall 2 s, test margin a literal 2 s, the supervisor deadline deliberately longer. Asserts exit 124 and that the container is gone only after the guard's destroy. The E19 check is dropped (round 3); control-container `--rm` is an `equivalence_smoke` check, not this leaf's.
4. `b09_host_uid_sealable`, `#[cfg(target_os = "linux")]` and run on Linux CI only. `/// Guards: B09 — files written in the container belong to the host uid.` `/// Oracle: stat uid of the files, and a chmod of the run dir succeeds.` `/// Bite: omit --user <uid>:<gid>.` On a macOS host the test is compiled out; the gate says so.
**Deliverables**: `crates/candler-core/tests/container_run_e2e.rs` (`b06_kernel_facts`, `b08_self_expiry`, `b09_host_uid_sealable`)
**Consistency Checks**: `cargo nextest run -p candler-core --run-ignored only --no-tests=fail -E 'binary(guard_container_e2e) & (test(/b06/) | test(/b08/))'` (expected: PASS)
**Commit**: `test(isolation): prove the kernel facts of the agent container`
