**Goal**: `isolation::container::{stop,guard,sweeper}` and `isolation/docker.rs` give the one place that destroys a container or a network: `ContainerGuard` destroys only an id that is recorded or job-labelled, re-verified by `docker inspect` immediately before each verb, never by name, prefix or pattern; `ContainerStopHook` runs it from the ladder; `LabelSweeper` finds a lost job's labelled containers; and no other module holds a destroy verb.

## Step 1: The real DockerDriver and DestroyDriver
**Goal**: One module runs docker, and its destroy half is a separate type that only the guard can hold.
**Implementation Logic**:
1. `isolation/docker.rs`: `pub struct DockerCli { sup: Arc<Supervisor>, env: ClientEnv }` implementing `DockerDriver` (create-free reads and builds: `inspect`, `ps_by_label`, `network_inspect`, `image_inspect`, `build`, `run_captured` pass-through) and a second type `pub struct DockerDestroyer { cli: Arc<DockerCli> }` implementing `DestroyDriver` (`stop`, `rm`, `network_rm` only). Every call goes through `Supervisor::run_captured` (I15), with a timeout, the client env allowlist `DOCKER_HOST`, `DOCKER_CONTEXT`, `HOME/.docker` and nothing else. Async methods are `fn m<'a>(&'a self, id: &'a ContainerId) -> BoxFuture<'a, Result<_, DockerError>>`, with `'a` on self and every borrowed argument (round 3 N1).
2. `DockerDestroyer`'s constructor is `pub(super)`, so only `guard.rs` can build one; `DockerDriver` has no destroy method, so no read path can destroy. This is the structural half of B16.
3. `ps_by_label(&self, scope: &LabelFilter)` takes a typed filter (`candler.job=<id>`, optionally `candler.run`), never a free string, and refuses an empty value. `inspect` parses `docker inspect --format '{{json .}}'` into `ContainerInfo { id, labels, state, image_id, cidfile }` and refuses a short id or a name in the id position (`DockerError::NotAFullId`).
4. Class A, in `mod scaffold`: argv golden vectors through a recording `Supervisor` fake, and parser tables over literal `docker inspect` JSON captured from the spike. The id, label and network-name types come from S3.
**Deliverables**: `crates/candler-core/src/isolation/docker.rs` (`DockerCli`, `DockerDestroyer`, `ClientEnv`, `LabelFilter`, `ContainerInfo`, `DockerError`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::docker/)'` (expected: PASS)
**Commit**: `feat(isolation): run the docker cli through the supervisor`

## Step 2: ContainerGuard, the one destroy rule
**Goal**: An id is destroyed only after the single rule (R10) has passed on a fresh inspect.
**Implementation Logic**:
1. `guard.rs`: `pub struct ContainerGuard { inspect: Arc<dyn DockerDriver>, destroyer: DockerDestroyer, events: EventSink }`. `pub fn destroyable<'a>(&'a self, c: &'a ContainerRef, scope: &'a SweepScope) -> BoxFuture<'a, Result<ContainerInfo, GuardRefusal>>`; `pub fn destroy<'a>(&'a self, c: &'a ContainerRef, scope: &'a SweepScope) -> BoxFuture<'a, Result<Destroyed, GuardError>>` (round 3 N3: `&ContainerRef`, `&SweepScope`); `pub fn destroy_network<'a>(&'a self, n: &'a NetworkRef, scope: &'a SweepScope) -> BoxFuture<'a, Result<(), GuardError>>` (R9).
2. The rule (R10), applied to the inspect result of the same call: the id is a full 64-hex id; the scope is `SweepScope { Run(RunKey), CurrentJob, Lost(JobId) }` (D14): `Run` is a run's own end (the label `candler.run` must equal the key), `CurrentJob` the job teardown (gateway and network), `Lost` the recovery, where every container labelled for that job is in scope; the labels carry `candler.job` equal to the scope's job; `candler.role` is `agent` or `gateway` and equal to the record's role; a current-job container needs a record in `children/` or an in-scope `candler.run`, else `GuardRefusal::Unrecorded`; `candler.role=control` is refused always (round 3, B10 row); a name, a prefix, a glob, `all` and an empty string are never accepted by the types (`ContainerRef` holds only a full id).
3. Refusals: `GuardRefusal::{Unrecorded, OtherJob, Unlabelled, Mismatch}` plus `Control`; each carries what it compared, none carries a token. Every refusal is logged as an event.
4. Verbs, per destroy: `inspect` then check, `stop` with a short timeout, then `inspect` again, check the same id and the same labels, then `rm`. A second inspect whose labels or id differ refuses the `rm` (`GuardRefusal::Mismatch`), which closes the cid-reuse window as far as the CLI allows. `destroy_network` inspects the network's `candler.job` label the same way and removes it only after every container on it is destroyed or absent.
5. The guard takes its job set from the scope; it never lists "all containers". `rm` is `docker rm -v <id>` without `-f`: `-v` removes only that container's anonymous volumes, which is its copy of the agent env (ruling A13). No `docker volume rm` exists anywhere.
6. Class A, in `mod scaffold`: the recording `DestroyDriver` and scripted inspect answers from `test-support`, with literal call lists. B10 and B11 land in Step 5.
**Deliverables**: `crates/candler-core/src/isolation/container/guard.rs` (`ContainerGuard`, `destroyable`, `destroy`, `destroy_network`, `GuardRefusal`, `GuardError`, `Destroyed`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::container::guard/)'` (expected: PASS)
**Commit**: `feat(isolation): destroy containers only through one verified guard`

## Step 3: The stop hook and the label sweeper
**Goal**: The ladder destroys the job's container and sweeps what the record missed, and a hook failure never skips a step.
**Implementation Logic**:
1. `stop.rs`: `ContainerStopHook { guard: Arc<ContainerGuard>, sweeper: Arc<dyn ContainerSweeper>, job: JobId }` implementing `StopHook`: `pre_stop<'a>(&'a self, ..) -> BoxFuture<'a, Result<(), HookError>>` (R6) runs `docker stop` of the recorded agent container through the guard; `destroy<'a>(&'a self, ..) -> BoxFuture<'a, Result<ContainerSweep, HookError>>` destroys the recorded containers and the network through the guard, then runs the sweep. This leaf owns `ContainerStopHook::new(guard, sweeper, job)` and `impl EndFacts for ContainerStopHook` (A1), whose `final_inspect(&self) -> Option<ContainerOutcome>` (round 3 N5) reads the exit state of the agent container before destroy, for the supervisor's outcome. The hook attaches per request only through `SpawnRequestBuilder::stop_hook` (R7).
2. In the supervisor's stop path, `supervise/stop.rs`, which S3 lands with the R1 gate and the R6 behaviour and this leaf never edits (D19): an `Err(HookError)` from `pre_stop` or `destroy` is logged as that step's outcome with the error and the ladder continues to the group signal and the sweep (R6). It is never an early return.
3. `sweeper.rs`: `LabelSweeper { docker: Arc<dyn DockerDriver>, guard: Arc<ContainerGuard>, view: Arc<dyn JobView>, timeout: Duration }` implementing `ContainerSweeper` (R17) with its own timeout. `sweep<'a>(&'a self, scope: &'a SweepScope) -> BoxFuture<'a, Result<ContainerSweep, SweepError>>` lists `children/` through `JobView` (R8: `ChildEntry::{Process, Container, Unreadable{path, error}}`), then `ps_by_label(candler.job=<scope job>)`, and passes each labelled id to the guard. An `Unreadable` entry is reported in `ContainerSweep.unreadable` and sets `ContainerSweep.unknown`, never treated as "no container" (B15); valid siblings are still handled. When `unknown` is true, the event `container.sweep_incomplete` is emitted (R25). A live sibling job's containers are outside the scope and are never listed.
4. Class A, in `mod scaffold`: fake `JobView`, recording driver, scripted `ps_by_label`.
**Deliverables**: `crates/candler-core/src/isolation/container/stop.rs` (`ContainerStopHook`, `final_inspect`); `crates/candler-core/src/isolation/container/sweeper.rs` (`LabelSweeper`, `SweepError`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::container::(stop|sweeper)/)' && cargo clippy -p candler-core --all-targets -- -D warnings` (expected: PASS)
**Commit**: `feat(isolation): sweep labelled containers from the stop hook`

## Step 4: Real-container tests B12 and B13
**Goal**: The real docker CLI confirms the sweep scope and the client-killed case.
**Implementation Logic**:
1. `#[path]` modules `tests/container_stop_e2e.rs` for the S3 harness. Every test builds its driver inside an `AllowlistDriver` that panics on any id the test did not create, and asserts only through `candler.job=<test id>`, a unique id per test. None calls `kill`, `pkill`, `killall`, `docker rm -f $(...)` or a prune; the client kill goes through the `Signaller` guard with the recording off and the pid from the supervisor's own record. Before spawning tests: `git diff --quiet HEAD -- crates/candler-core/src && cargo clean -p candler-core && cargo nextest run -p candler-core -E 'binary(guard_signal)'`.
2. `b12_sweep_scope`. `/// Guards: B12 — the sweep is scoped by the job label.` `/// Oracle: docker ps -a --filter label=candler.job=<id> before and after, inside the allowlist wrapper.` `/// Bite: drop the candler.job filter from ps_by_label (inside the allowlist wrapper only).` Three jobs with `candler.job` values `t-<id>-live`, `t-<id>-lost` and the test job: a live sibling's container survives; the lost job's unrecorded container is destroyed; the per-job network is removed through `destroy_network`.
3. `b13_client_killed_container_gone`. `/// Guards: B13 — a client death never leaves the agent container.` `/// Oracle: no container labelled for the job after the ladder finishes.` `/// Bite: make StopStep::DestroyContainer a no-op.` An `ignore-term` agent; the docker client is killed through the guard; the ladder's `destroy` step plus the sweep remove it.
4. After every run the test asserts `docker ps -a --filter label=candler.job=<test id>` is empty and calls the guard on the leftover only if the test failed, so a failing run cannot leak.
**Deliverables**: `crates/candler-core/tests/container_stop_e2e.rs` (`b12_sweep_scope`, `b13_client_killed_container_gone`)
**Consistency Checks**: `cargo nextest run -p candler-core --run-ignored only --no-tests=fail -E 'binary(guard_container_e2e) & (test(/b12/) | test(/b13/))'` (expected: PASS)
**Commit**: `test(isolation): prove the sweep scope and the client-killed case`
