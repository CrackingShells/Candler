## Step 2: Run the one-cell job and check it against the feature map
**Goal**: One valid run, sealed, with every check script run against its real artifacts.
**Implementation Logic**:
1. `candler run experiment.toml` from the work dir. While the job runs, capture mid-run, read-only and only for containers labelled with this job: `docker inspect` of the agent (as `INSPECT_JSON`) and of the gateway, `docker logs` of the gateway, and set `EXEC` to `docker exec <agent cid>`. Then `candler ps` and `candler watch <job> --json` once each. Wait for `job.ended`.
2. Inputs for the checks: `WORKSPACE_DIR` and `HOME_DIR` from the run dir, `STREAM_JSONL` from the raw stream, `PROVENANCE_JSON` from a `jq` projection of `manifest.json` that maps each of the ten fields of `provenance_fields.txt` per §14 as completed by S0, `RUN_DIR`, `JOB_DIR`, `STORE_DIR`, `CANARY`. Provisioning checks (`venv_*`, `layout`, `planner_pin`, `env_scrubbed`, `host_isolation`, `non_root`, `benign_devices`, `manifest_outside`, `no_reference_answers`) run through `EXEC` mid-run, which reflects the pre-run state except for what the agent has already done; the report says so per check.
3. Run all 31 scripts, then the provenance, event-order and `preflight` gates. X8: the first prompt in the trace equals the template filled with the cell's values. X10: the gateway log shows traffic to the configured upstream only. Record each result with the script's one-line message.

**Consistency Checks**: `for c in $(jq -r '.[]|select(.check!=null)|.check' /Users/hacker/Documents/tmp/claude-worktrees/Candler/modest-benz-e1d863/__roadmap__/m2b-execution-parity/feature_map/feature_map.json | sort -u); do sh /Users/hacker/Documents/tmp/claude-worktrees/Candler/modest-benz-e1d863/__roadmap__/m2b-execution-parity/feature_map/checks/$c.sh || echo "FAIL $c"; done` (expected: no FAIL line)

## Step 3: Resume after a kill, then force a deviation
**Goal**: A killed run is sealed and numbered, resume replays stored values, and a moved tag is refused and then forced.
**Implementation Logic**:
1. Set `replicates = 2`. `candler run`; when replicate 2's agent container exists, `candler kill <job> -y` (the only way this smoke stops anything: no `kill`, `pkill` or `docker` destroy by hand). Check the run is sealed `invalid(killed)`, then `candler run` again: replicate 2 gets attempt 2, replicate 1 is untouched, and `resume_runs.sh` exits 0. X23 is this step.
2. Set `replicates = 3`. In the scratch clone, move the tag to another commit (`git tag -f`, in the clone only). `candler run` refuses and names the tag-to-commit path. `candler run --force` runs the new replicate with a `deviations[]` entry; the sealed runs' `sha256` are unchanged (X22). If the treatment source cannot be pointed at the scratch clone, report that as a finding and use the next resume re-check that the setup can change (the report names which one was exercised).
3. At most six agent runs in the whole leaf (replicates 1, 2 and 2 again, 3, the leak run, and one spare). A failure caused by a Candler defect stops the leaf and is reported; it is not retried more than twice without Eliott's go.
**Deliverables**: the third section of the leaf report (the attempt list, the deviation record, the `sha256` table before and after)
**Consistency Checks**: `sh /Users/hacker/Documents/tmp/claude-worktrees/Candler/modest-benz-e1d863/__roadmap__/m2b-execution-parity/feature_map/checks/resume_runs.sh` with `STORE_DIR` set to the smoke store (expected: PASS)
**Commit**: `reports(orchestrator): record the smoke resume and forced deviation`

## Step 4: Force an input leak and scan for the canary
**Goal**: An output equal to an input is sealed `invalid(input_leak)`, and the token appears nowhere in the whole store.
**Implementation Logic**:
1. X32: a second experiment whose prompt tells the agent to copy its input file to an output path. The run is sealed `invalid(input_leak)`, and the same cell with a changed byte stays valid (the control; recorded from a hand-made input, not a second paid run, if the first run already produced a valid output).
2. The canary scan of the gate over every location listed, including the leak run and the killed run, and the final `docker ps -a`, `docker network ls` and `ps eww` checks for every job id of the smoke. The scan reads the real token from its variable and reports only the result.
3. Clean up only what this smoke made: the job ids it recorded, through `candler kill` or the guard; no `docker rm`, `stop`, `prune` or `kill` by hand.
**Deliverables**: the fourth section of the leaf report (X32, the canary result, the leftover checks)
