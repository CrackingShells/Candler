## Step 1: Read the spec, take the session, the lock and the subreaper
**Goal**: A supervisor process leads its own session, holds the job lock for its life, has its spec from stdin, and on Linux adopts every orphaned descendant.
**Implementation Logic**:
1. `detach_session() -> Result<(), RuntimeError>` calls `rustix::process::setsid()`. It fails when the caller leads a process group, so the launcher must never spawn the supervisor with `process_group(0)` (step 4).
2. `become_subreaper() -> Result<(), RuntimeError>`: under `#[cfg(target_os = "linux")]`, `rustix::process::set_child_subreaper(Some(getpid()))`; on other targets it returns `Ok(())` and the accepted gap in R04 applies. No `unsafe`.
3. `read_spec(job_dir: &Path, stdin: impl Read) -> Result<JobSpec, RuntimeError>` (D8) reads stdin to EOF, checks the SHA-256 of those bytes against `spec_digest` in `job.json`, and only then deserialises; a mismatch is `RuntimeError::SpecDigest` before the lock is taken. `JobSpec` is serde-internal and never stored.
4. `supervise_entry<'a>(spec: JobSpec, body: JobBody) -> BoxFuture<'a, Result<JobOutcome, RuntimeError>>` (fills the S3 stub; `type JobBody = fn(Runtime, JobSpec, JobControl) -> BoxFuture<'static, JobOutcome>`, D12) runs in this order, and nothing signals or spawns before the handler exists:
   1. `SignalWatch::install(control.clone())` (step 3), then `detach_session`, then `become_subreaper`;
   2. `JobDir::open`, then `JobLock::acquire`; a held lock returns `RuntimeError::AlreadySupervised` and exits without touching the dir;
   3. load user `Config`; build `Runtime` with an `Arc<Supervisor>` whose sink is `JobEvents`, the real `DockerDriver` from `container_stop` and `Slots`; then `let g = sup.guard()`, build `ProcMarkerSweeper::new(g)` (step 2) and install it with `Supervisor::with_sweeper` (D11);
   4. emit `job.started` right after the lock (D10) and set the job state `running`; reap lost jobs (5);
   5. `body(runtime, spec, control)`; then `sweep_orphans` (step 2), emit `job.ended` from `JobOutcome.end`, set the state `ended`, release the lock last. A body that panics or a `RuntimeError` after `job.started` still emits `job.ended(failed)` and releases the lock.
5. Startup reaping: `reap_lost_jobs(&Runtime, own: &JobId)` lists the store's job dirs through `job_store`, skips its own, and for each one `jobs::lost::classify` calls `Lost` it calls `jobs::lost::recover(&sup, &LabelSweeper, &dir)`; the sweeper reaches `recover` through the `Supervisor` (D11). It holds our lock first, so two supervisors never reap one dir at once; a dir it cannot read is evented and skipped, never read as clean. No other code in this leaf touches another job's children or containers.
**Deliverables**: `crates/candler-core/src/jobs/runtime/{mod.rs,session.rs}` (`RuntimeError`, `read_spec`, `supervise_entry`, `detach_session`, `become_subreaper`, `reap_lost_jobs`); a class-A `#[cfg(test)] mod scaffold` for the order of the entry steps and the digest check
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/runtime::scaffold/)' && cargo clippy --target x86_64-unknown-linux-gnu -p candler-core --tests -- -D warnings` (expected: PASS)
**Commit**: `feat(jobs): hold the job lock as a detached subreaper`

## Step 2: Sweep strays by marker and by reparenting
**Goal**: After a run stops, every process that carries its marker, and after the job every orphan reparented to this supervisor, is killed through the guard and reaped by pid.
**Implementation Logic**:
1. `ProcMarkerSweeper::new(guard: Arc<Guard>)` implements M1's `StraySweeper::sweep(&Marker) -> Vec<StrayProcess>` (D11). Linux only: read `/proc/<pid>/environ` of every same-uid process and keep those whose `CANDLER_RUN` equals the marker exactly. On macOS it returns an empty result, which is the recorded gap. It never matches by prefix and never matches its own pid or its own group.
2. Fill `Guard::signal_marked(pid, start, &Marker, Signal)` in `supervise/signal.rs`: right before the kill it re-reads the pid's environ and start time, and refuses a pid at or below 1, its own pid, its own pgid, a changed start time (pid reuse), and any pid without the exact marker. The sweeper kills only through it; a stray it refuses is returned as not killed and evented, never signalled another way.
3. `Guard::signal_adopted(pid, start, Signal)` (D23, filled here): right before the signal it verifies the pid's parent is this process and its start time matches, signals that one pid only (never a group), and refuses a pid at or below 1, its own pid and its own pgid; the caller reaps with `waitpid(pid)`.
4. `sweep_orphans(&Runtime) -> Vec<StrayProcess>` (Linux, after the last run is sealed): scan `/proc/<pid>/stat` for `ppid == own pid`, drop every pid or group the guard holds, and treat the rest as orphans reparented to the subreaper whose environment was scrubbed. Such a pid has no marker, so `signal_marked` would refuse it by design: kill it with `Guard::signal_adopted(pid, start, KILL)`, never `Guard::register`, which would make it look spawned. Run once at job end only: during a job an unattributable orphan may belong to another live run. The stat parse reuses M1's `comm`-aware rule (the `comm` field ends at the last `)`).
5. `reap_by_pid(pids: &[StrayProcess])` calls `rustix::process::waitpid(Some(pid), WaitOptions::NOHANG)` per killed pid, with a bounded retry (at most the stop grace), so a killed stray never stays a zombie. There is no wait on `None` and no negative pid anywhere in the crate.
6. The refusals of `signal_marked` and `signal_adopted` (each case above, never calling the recorder) and a positive control each (exact marker, unchanged start; our child, unchanged start) are new rows of M1's I22 refusal test in `tests/guard_signal.rs`, on the recording `Signaller`. They stay after close-out; no new B-test.
7. B33 in `tests/guard_job_runtime.rs`, `#[cfg(target_os = "linux")]`, named `b33_setsid_descendant_dies`: the test writes a one-line wrapper that starts M1's `tree.sh` detached grandchild through `env -i <absolute perl>`, and every grandchild sleeps at most 20 s so a failed bite leaves nothing for the test to kill. It calls `become_subreaper` (production function), supervises the tree through `Child::stop`, runs `sweep_orphans`, then asserts by `kill(pid, 0)` or a changed start time that every pid the tree wrote is gone. Doc lines: `Guards: I15 — a setsid'd, TERM-ignoring descendant dies through the subreaper.` / `Oracle: the OS (kill(pid,0), /proc start time), M1's tree.sh fixture.` / `Bite: remove the set_child_subreaper call.` The positive control is the same tree with `become_subreaper` called, which the test body is.
**Deliverables**: `crates/candler-core/src/jobs/runtime/{sweep.rs,reap.rs}` (`ProcMarkerSweeper`, `sweep_orphans`, `reap_by_pid`); `crates/candler-core/src/supervise/signal.rs` (`Guard::signal_marked` and `Guard::signal_adopted` bodies); `crates/candler-core/tests/guard_signal.rs` (the new refusal rows); `crates/candler-core/tests/guard_job_runtime.rs` (`b33_setsid_descendant_dies`)
**Consistency Checks**: `cargo clippy --target x86_64-unknown-linux-gnu -p candler-core --tests -- -D warnings && cargo nextest run -p candler-core -E 'binary(guard_signal) | binary(guard_layering_i22)'` (expected: PASS)
**Commit**: `feat(jobs): sweep strays by marker and by reparenting`

## Step 3: Turn SIGTERM into a killed job
**Goal**: A SIGTERM at any moment reaches the body as `JobCause::Killed`, the body's children die, and the job ends `killed` with the lock released.
**Implementation Logic**:
1. `SignalWatch::install(control: JobControl) -> io::Result<SignalWatch>` creates the `tokio::signal::unix` streams for SIGTERM and SIGINT before any other work, and spawns one task that, on either, sends `Some(JobCause::Killed)` once on the `watch::Sender` it holds a clone of (D12). The streams exist before `JobLock::acquire`, so a signal during startup is queued, not lost; the body's receivers see the value whenever they subscribe. The handler never signals a process itself: live runs stop through their own ladder with the cause `killed`, so E12 and the ends table keep their order (R2). Sealing runs `killed` is B29's.
2. After the body returns, `supervise_entry` emits `job.ended` from `JobOutcome.end` (the schemas' `JobEnd`; `JobEndedBy` does not exist, D13) and sets the job state.
3. B32 in `tests/guard_job_runtime.rs`, named `b32_sigterm_seals_killed`: a helper `#[test] fn supervisor_child()` does nothing unless `CANDLER_TEST_SUPERVISOR_JOB` is set, in which case it runs `supervise_entry` with a fake body that starts two real `sleep` children through the `Supervisor`, records their pids in a file, awaits `Killed` on its `JobControl` receiver, writes `killed-seen`, stops the children and returns `JobEnd::Killed`. The test re-executes `std::env::current_exe()` with `--exact supervisor_child --nocapture`, waits for the pid file, sends SIGTERM to the pid of the `Child` it holds (the helper refuses any pid not equal to `child.id()` and any pid at or below 1), and waits for exit. Doc lines: `Guards: I15, I20 — SIGTERM delivers Killed to the body, its children die, job.ended(killed) is last, the lock is free.` / `Oracle: the OS and the literal event kinds.` / `Bite: the SIGTERM handler does not send Killed.` The control in the same test: before the signal, the lock is held and no `job.ended` exists. The supervisor child wraps the real `Signaller` in a logging pass-through (test side, in `support/job_runtime.rs`); the SIGTERM handler only sends `Killed` on `JobControl`, so every stop goes through `StopHandle` and the `ContainerGuard`, never a direct group signal, container destroy or re-raise (D24).
**Deliverables**: `crates/candler-core/src/jobs/runtime/signals.rs` (`SignalWatch`); `crates/candler-core/tests/guard_job_runtime.rs` (`b32_sigterm_seals_killed`, `supervisor_child`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'binary(guard_job_runtime) & test(/b32/)'` (expected: PASS)
**Commit**: `feat(jobs): end a job killed on SIGTERM`

## Step 4: Detach the launcher and close the leaf
**Goal**: `detach` starts the supervisor with its spec on stdin and returns without waiting for it, and the leaf's scaffolding is gone.
**Implementation Logic**:
1. `detach(args: DetachArgs {exe: PathBuf, job_dir: PathBuf, spec: Vec<u8>, env: Vec<(String, String)>}) -> Result<DetachedJob {pid: u32, job: JobId}, RuntimeError>` (D8) runs `std::process::Command` of `exe` with the hidden verb `supervise --job <id>`, stdin a pipe that receives `spec` and is closed, stdout and stderr both to `<job-dir>/supervisor.log`, `env_clear` plus the caller's allowlist (`PATH`, `HOME`, `XDG_STATE_HOME`, `DOCKER_HOST`, `DOCKER_CONTEXT`), and no `process_group(0)` (the supervisor calls `setsid` itself). It then polls `JobLock::probe` until the lock is held or a deadline passes (`RuntimeError::DidNotStart`, naming the job dir and `supervisor.log`). It never waits on the supervisor. It drops the `Child`; the launcher exits straight after, so the supervisor is adopted and no zombie client remains.
2. Delete the class-A scaffolding (`mod scaffold` in `session.rs`, `sweep.rs` and `signal.rs`, any `tests/scaffold_job_runtime.rs`), confirm `guard_job_runtime` holds exactly B32 and B33 plus the `supervisor_child` helper, and write the bite record in the leaf report: the B32 and B33 mutations, each tried, each restored with `git checkout --`, with the failing assertion quoted, and the verifier's `signal_marked` and `signal_adopted` cases on the recording `Signaller`.
**Deliverables**: `crates/candler-core/src/jobs/runtime/detach.rs` (`DetachArgs`, `DetachedJob`, `detach`); the leaf report `__reports__/m2b-execution-parity/job_runtime_report_v0.md` (the bite record)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'binary(guard_job_runtime) | binary(guard_layering_i22)' && ! git grep --untracked -n -e 'mod scaffold' -e 'scaffold_' -- crates/candler-core/src/jobs/runtime crates/candler-core/src/supervise/signal.rs crates/candler-core/tests` (expected: PASS)
**Commit**: `test(jobs): prove a killed job leaves no survivor`
