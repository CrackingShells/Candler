# Gateway: token outside the agent

**Goal**: `isolation::gateway` starts a per-job nginx sidecar on a per-job `--internal` network (design B) that holds the real token, injects it by `docker exec -i` stdin into a tmpfs, forwards only to the Anthropic upstream, and scrubs the token from logs and bodies, so the agent container holds a dummy token, has no route out except the sidecar, and the real token appears nowhere the agent can read.

## Step 1: The sidecar image and its nginx config
**Goal**: A pinned nginx sidecar that cannot forward until the token arrives and never logs it.
**Implementation Logic**:
1. `assets/docker/gateway/Dockerfile`: `FROM nginx@sha256:a8b39bd9cf0f83869a2162827a0caf6137ddf759d50a171451b335cecc87d236`, a copy of `nginx.conf.template` and `entrypoint.sh`, `USER nginx`, no `ENV` or `ARG` carrying a token. The pinned image carries `wget` for the readiness probe (D20).
2. `entrypoint.sh`: waits (bounded, 60 s, then exits non-zero) for `/run/gw/auth.conf` on a 0700 tmpfs, then `exec nginx -g 'daemon off;'`. The file is written by the supervisor through `auth.tmp` and `mv`, so nginx never reads a partial file. Until it exists, nothing listens on the proxy port, so the sidecar fails closed.
3. `nginx.conf.template`: one `server` on `:8080`; `include /run/gw/auth.conf` (a single `proxy_set_header Authorization "Bearer <token>"`); `proxy_pass https://<upstream host>`; `proxy_ssl_server_name on; proxy_ssl_verify on; proxy_ssl_trusted_certificate <ca>; resolver <internal DNS>` and `proxy_set_header Host <host>`; `proxy_buffering off` (SSE); `limit_conn_zone "all" zone=gw:1m; limit_conn gw <max_parallel>; limit_conn_status 429` (the spike found the key `$server_name` inert); `sub_filter` of the token to a fixed placeholder with `sub_filter_once off` and `sub_filter_types *`, and `proxy_hide_header` for names only (not a body scrub); `access_log` with a format that omits `Authorization` and the prompt and includes the model through `map $request_body $model` (the unquoted regex form, the quoted-tilde form matches nothing); `error_log` at `warn`, no `debug`. The upstream host, the CA and `max_parallel` are rendered by the supervisor into non-secret template vars.
4. `GET /healthz` returns 200 and proves only that nginx is up. `/v1/models` is the readiness, since it proves the proxy path and the token.
5. Class A: render the template for a literal set of vars and run `docker run --rm candler-gateway nginx -t` against the rendered file in a control container (role `control`, job `preflight`, `--rm`, `--network none`).
**Deliverables**: `assets/docker/gateway/{Dockerfile,entrypoint.sh,nginx.conf.template,.dockerignore}`
**Consistency Checks**: `grep -q '^FROM nginx@sha256:a8b39bd9' assets/docker/gateway/Dockerfile && ! grep -nE 'ENV|ARG' assets/docker/gateway/Dockerfile | grep -iE 'token|key'` (expected: PASS)
**Commit**: `feat(isolation): add the nginx gateway sidecar image`

## Step 2: Gateway::start with the token on stdin
**Goal**: The supervisor starts the sidecar and injects the token without it crossing an argv, an env or a file the agent can read.
**Implementation Logic**:
1. `isolation/gateway.rs`: `pub struct DockerGateway { image: ImageRef, upstream: UpstreamConfig, max_parallel: u32 }` implementing `Gateway`. R16: `start<'a>(&'a self, sup: &'a Supervisor, docker: &'a dyn DockerDriver, job: &'a JobId, net: &'a NetworkName, token: &'a dyn SecretSource) -> BoxFuture<'a, Result<GatewayHandle, GatewayError>>`, with `'a` on self and every borrowed argument (round 3 N1). `GatewayHandle { container: ContainerRef, base_url: Url, net: NetworkName }` has no token.
2. The sequence: create the per-job network `--internal` with `--label candler.job=<job>` (through a `docker network create` argv, no destroy verb here), `docker run -d` the sidecar with labels `candler.job`, `candler.role=gateway`, `candler.run`, `--read-only`, tmpfs `/run/gw` mode 0700 owned by the nginx uid, tmpfs `/tmp` and `/var/cache/nginx`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--pids-limit`, `--memory`, `--cidfile`, no `--rm`, `--network <net>` joined to the internal network only; the container is recorded in `children/` before the token is injected. A `bridge` isolation adds an extra bridge network to the sidecar only, so the agent keeps the gateway route and nothing else.
3. Token injection: `docker exec -i <gw> sh -c 'umask 077; cat > /run/gw/auth.tmp && mv /run/gw/auth.tmp /run/gw/auth.conf'`, run through `Supervisor::run_captured` with a `StdinSpec` carrying the rendered `proxy_set_header` line. The line is built from `SecretSource::expose()` inside the one function that needs it, as a `Zeroizing<String>` that never reaches a log, an event or an error (errors name the secret by label only). The token is never in an argv or an env of any process on the host.
4. Readiness: poll `docker exec <gw> wget -q -T 2 -O- http://127.0.0.1:8080/v1/models` with bounded retries. Failure is `GatewayError::NotReady`; the fake-upstream 401 or the 429 is distinguished. `GatewayStatus::Unavailable { reason }` is the status the supervisor stores when the sidecar fails (round 3), the run is `invalid(gateway)`.
5. Restart: `reinject<'a>(&'a self, ..) -> BoxFuture<'a, Result<(), GatewayError>>` repeats step 3 after a `docker restart`, which empties the tmpfs.
6. Teardown is the guard's: `ContainerGuard::destroy` of the sidecar, then `destroy_network`. This leaf holds no `stop`, `rm` or `network rm`.
7. Class A, in `mod scaffold`: the recording `DockerDriver` for the create and run argv vectors (the token absent from every vector), a `StdinSpec` capture asserting the token appears only on stdin, and an `Err` path test where the token source fails.
**Deliverables**: `crates/candler-core/src/isolation/gateway.rs` (`DockerGateway`, `UpstreamConfig`, `start`, `reinject`, `GatewayError`)
**Consistency Checks**: `cargo nextest run -p candler-core -E 'test(/isolation::gateway/)' && cargo clippy -p candler-core --all-targets -- -D warnings` (expected: PASS)
**Commit**: `feat(isolation): start the gateway with the token on stdin`

## Step 3: Log scrub, canary helper and the TLS fake
**Goal**: The test helpers that make B17 meaningful exist, and TLS to the upstream is proven locally.
**Implementation Logic**:
1. `fn scrub(line: &str, token: &str) -> String` is not needed for logs (the nginx log format omits the header); instead `GatewayLogs::read<'a>(&'a self, ..) -> BoxFuture<'a, Result<String, GatewayError>>` reads `docker logs` of the sidecar for the leaf report, and the canary helper asserts the token's absence. `pub fn assert_clean(canary: &str, haystacks: &[(&str, &[u8])]) -> Result<(), Leak>`, test-only in `#[cfg(any(test, feature = "test-support"))]` never on a production edge, scans the bytes of each named source for the canary and for its base64 and its first 16 characters, and names the source in the `Leak`.
2. The canary is `format!("cnd-canary-{}", uuid)`, random per test, passed to the sidecar by the same stdin path as a real token. The spike gotchas apply: probes feed the canary on stdin and skip `/dev` when scanning the process tree.
3. The local TLS fake (D25): a self-signed CA and server certificate made at test time with the `openssl` CLI, served by a Python-stdlib script (`ssl` plus `http.server`, in `crates/candler-core/tests/fixtures/gateway/`) running in a labelled container of the pinned `python:3.12-slim-bookworm` image, on a bridge network shared with the sidecar (the fake is the only test using one), returning a canned `200` and, on a second route, an error page that echoes the `Authorization` header. The test asserts SNI, `Host` and the real token at the fake, and that the body the agent sees has the token replaced (the `sub_filter`), and that a certificate the sidecar does not trust fails closed. No Rust TLS crate is added: `ring` needs a Linux C cross-compiler that the LINUX gate cannot assume on macOS (D25).
4. The model log probe: send a request body `{"model":"m-<rand>"}` and assert the access log line holds the model and no `Authorization`.
**Deliverables**: `crates/candler-core/src/isolation/gateway.rs` (`GatewayLogs`, `assert_clean`, `Leak`); `crates/candler-core/tests/gateway_e2e.rs` (the TLS-fake helper and the log probe test)
**Consistency Checks**: `cargo nextest run -p candler-core --run-ignored only --no-tests=fail -E 'binary(guard_container_e2e) & test(/gateway_tls|gateway_log/)'` (expected: PASS)
**Commit**: `test(isolation): add the canary helper and the TLS upstream fake`

## Step 4: B17 and B18 against real containers
**Goal**: The token is demonstrably outside the agent, and the agent is demonstrably off the network.
**Implementation Logic**:
1. `#[path]` module `tests/gateway_e2e.rs` of the S3 harness. Every test wraps its driver in the `AllowlistDriver` and asserts only through `candler.job=<test id>`. No `kill`, `pkill`, `docker rm -f $(...)` or prune; teardown is `ContainerGuard`. Before spawning tests: `git diff --quiet HEAD -- crates/candler-core/src && cargo clean -p candler-core && cargo nextest run -p candler-core -E 'binary(guard_signal)'`.
2. `b17_canary_absent`. `/// Guards: B17 — the real token never enters the agent container.` `/// Oracle: a random canary with assert_clean over the agent env, /proc/1/environ, workspace, HOME, every labelled container's inspect, the gateway logs.` `/// Bite: put the real token in the agent's -e ANTHROPIC_API_KEY.` The testagent in `stream` mode runs a request through the sidecar to the TLS fake with the error route echoing `Authorization`; the dummy token appears in the agent (expected), the canary nowhere. Also asserts that the dummy token fails to authenticate against the fake when sent directly from a bridge container.
3. `b18_internal_network_no_route`. `/// Guards: B18 — the agent has no route to the host or the internet. /// Oracle: a connection from the agent to the host listener fails and to the sidecar succeeds; control: a bridge container reaches the host listener. /// Bite: drop --internal.` The host listener is a local TCP listener on the docker host gateway address. The internal network's own gateway IP answers connection refused, which the test tolerates (harmless while nothing listens).
4. On a Linux engine one CI probe repeats B18: the container-to-host path differs from Docker Desktop's. The gate lists the Linux run in the leaf report.
**Deliverables**: `crates/candler-core/tests/gateway_e2e.rs` (`b17_canary_absent`, `b18_internal_network_no_route`)
**Consistency Checks**: `cargo nextest run -p candler-core --run-ignored only --no-tests=fail -E 'binary(guard_container_e2e) & (test(/b17/) | test(/b18/))'` (expected: PASS)
**Commit**: `test(isolation): prove the token stays out of the agent container`
