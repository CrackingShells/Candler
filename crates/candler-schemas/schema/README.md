# Schema roots

Each `*.schema.json` file is one root: a JSON Schema 2020-12 document with its `$id` set to
`urn:candler:schemas:<name>`, generated by `schemars` from a struct in `candler-schemas/src` and
committed. The files are never edited by hand. A change to a wire struct or to its doc comment
changes the file, and the drift test fails until the files are regenerated:

```sh
CANDLER_BLESS_SCHEMAS=1 cargo nextest run -p candler-schemas drift
```

`tests/schema_drift.rs` compares every generated root with its file and refuses a `*.schema.json`
file that no struct generates. This README and any other file that does not end in `.schema.json`
are not roots. The roots are the ones on the `schemas@` line of
[R01 §The `schemas@` line holds](../../../__design__/architecture.md); sections below are in R01.

## Roots

The wire tag is the value of the `schema` property of the document, or of its header record where
the file holds a stream. A root without a tag is a record that travels inside a versioned message
or file, or a message of the evaluator protocol.

|---|---|---|---|
| `catalog-snapshot.schema.json` | `CatalogSnapshot` | `tool-catalog-snapshot/1` | Wire schema: tool-catalog snapshot |
| `child-record.schema.json` | `ChildRecord` | `child-record/1` | Process supervision |
| `evaluator-describe-result.schema.json` | `DescribeResult` | none; `protocol` is `{major, minor}` | Evaluator protocol (`describe` result) |
| `evaluator-evaluate-params.schema.json` | `EvaluateParams` | none | Evaluator protocol (`evaluate` params) |

## Stream roots

`normalised-trace` and `raw-frames` describe one line of a JSONL file: an object whose `kind` is
`header`, `session` or `event` for a trace, and `header` or `frame` for raw frames. The file holds
one header, then the other records.

`event-envelope` describes one line of a job's `events.jsonl`; `kind` selects the payload.

## Conventions the files share

- Patterns end with `(?![\s\S])` and spell white space as an explicit set, so ECMA 262, Rust and
  Python read them alike.
- A rule JSON Schema cannot state (`num ≤ den`, the weight rules, unique names, 64- and 32-bit
  integer limits) is enforced in Rust and stated in a `$comment`.
- Every record is an object; a list is refused, and `null` is not written for an absent field.
- The files carry no crate version. The `schemas@` tag line versions them as a set.
